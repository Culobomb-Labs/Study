    01

    La piattaforma Android

    Com'è fatto il sistema, a strati

    Android è un sistema software completo per telefoni e tablet: sistema operativo, librerie, un framework per le app e le app di base. Per sviluppare si usa l'SDK (librerie, strumenti, documentazione).

    L'architettura a strati

    Leggila dal basso verso l'alto: ogni strato usa quello sotto.

    ApplicazioniHome, Contatti, Telefono, Browser… e le nostre
    Application framework (Java API)View System, Content Providers, Package Manager, Activity Manager
    Librerie native + Android RuntimeWebKit, libc, OpenGL ES · ART
    HALinterfacce standard per audio, Bluetooth, fotocamera, sensori
    Kernel Linuxfile system, memoria, processi, rete, driver, batteria
    • Kernel Linux: i servizi base di un sistema operativo, più cose specifiche di Android (gestione batteria, low memory killer, comunicazione tra processi).
    • HAL (Hardware Abstraction Layer): nasconde le differenze tra un hardware e l'altro. Il livello sopra chiede "la fotocamera" senza sapere quale modello è.
    • Application framework: le funzioni del sistema esposte come API. Activity Manager gestisce il ciclo di vita delle app, Package Manager le installa, Content Providers danno accesso ai dati di altre app (es. la rubrica).

    Dal codice all'app: file .dex e ART

    Il codice Java/Kotlin viene compilato in bytecode Java. Lo strumento DX trasforma tutto in un unico file classes.dex (Dalvik EXecutable), che viene installato sul dispositivo ed eseguito da una macchina virtuale.

    Dalvik (API < 21)

    • Compila durante l'esecuzione (Just-In-Time)
    • Garbage collection che a volte blocca l'app
    • Più memoria e più batteria

    ART (API ≥ 21, Android 5.0)

    • Compila prima, di solito all'installazione (Ahead-Of-Time)
    • Garbage collection più efficiente
    • Meno memoria e meno batteria
    In una fraseUna VM apposita serve perché un telefono ha CPU più lenta, meno RAM e batteria limitata rispetto a un PC. Un'app che va bene su ART va bene anche su Dalvik, ma non il contrario.

    Domande lampo

    Qual è la differenza principale tra Dalvik e ART?

    Dalvik compila mentre l'app gira (JIT), ART compila prima, di solito quando l'app si installa (AOT). ART consuma meno memoria e batteria.

    A cosa serve l'HAL?

    Offre interfacce standard verso l'hardware (audio, fotocamera, sensori…), così i livelli superiori non dipendono dal modello del dispositivo.

    Cosa contiene classes.dex?

    Tutto il bytecode dell'app convertito nel formato Dalvik, più i dati necessari. È ciò che la VM esegue.

    02

    Versioni e livelli API

    I numeri che tornano in tutto il corso

    Ogni versione di Android ha un nome di dolce (in ordine alfabetico) e un livello API. Nel corso molte regole cambiano "da API X in poi". Questa è la mappa da tenere a mente:

    21Android 5.0 LollipopART sostituisce Dalvik. Notifiche heads-up.
    23Android 6.0 MarshmallowPermessi pericolosi chiesti a runtime.
    26Android 8.0 OreoCanali di notifica obbligatori. Pochi broadcast di sistema nel manifesto.
    28Android 9 PieConnessioni http in chiaro bloccate di default.
    29Android 10Storage "sandboxed": nasce MediaStore. Gli alarm non riportano l'app in primo piano.
    30Android 11Permesso "solo questa volta". <queries> per i Content Provider.
    31Android 12Alarm esatti richiedono un permesso. Alarm imprecisi entro un'ora.
    33Android 13Permesso POST_NOTIFICATIONS. READ_MEDIA_*.
    35Android 15App edge-to-edge (a tutto schermo) con gli insets.
    Questa tabella da sola risponde a un sacco di domande dello scritto.

    Domande lampo

    Da quale API i permessi pericolosi si chiedono mentre l'app gira?

    Da API 23 (Android 6.0). Prima si accettavano tutti all'installazione.

    Da quale API ogni notifica deve avere un canale?

    Da API 26 (Android 8.0). Senza canale la notifica non compare.

    03

    Android Studio e strumenti

    Progetto, emulatore, adb, debug

    Com'è fatto un progetto

    Si parte da File → New → New Project → Empty Views Activity. Dentro trovi:

    • Manifesto (AndroidManifest.xml): la carta d'identità dell'app. Permessi, activity, icona, servizi, receiver.
    • java/: il codice sorgente.
    • res/: le risorse. layout (le schermate in XML), values (stringhe, colori), drawable e mipmap (immagini e icone), menu.
    • Gradle: il sistema di build. Contiene le dipendenze dalle librerie (libs.versions.toml) e come compilare.

    Activity o AppCompatActivity?

    Activity è la classe base con il ciclo di vita standard. AppCompatActivity (da AndroidX) la estende e aggiunge retrocompatibilità: Toolbar, Material Design e temi chiari/scuri funzionano anche su Android vecchi. Nel dubbio si usa AppCompatActivity.

    Edge-to-edge e insets (API 35)

    Le app occupano tutto lo schermo. Gli insets sono le zone coperte da status bar, barra di navigazione, tastiera. Con setPadding si sposta il contenuto per non finirci sotto.

    Emulatore o telefono vero?

    Telefono reale

    • Veloce, esecuzione reale
    • Facile ruotare, toccare
    • Serve la modalità sviluppatore: tocca 7 volte Versione build, poi attiva Debug USB

    Emulatore (AVD)

    • Lento, è un simulatore e può avere bug
    • Facile simulare situazioni: batteria scarica, SMS in arrivo
    • Due emulatori comunicano con i "numeri" 5554 e 5556 (servono due AVD diversi)

    adb, Android Debug Bridge

    Strumento a riga di comando nella cartella platform-tools dell'SDK.

    adb devices                      # elenca dispositivi ed emulatori
adb shell pm list packages       # nomi dei package installati
adb shell pm path <package>      # dove sta l'apk
adb pull <percorso/app.apk>      # copia l'apk sul PC

    Debug

    • Debugger: Run → Debug. Metti i breakpoint cliccando accanto al numero di riga; l'app si ferma lì e puoi guardare variabili, stack delle chiamate, watch, ed eseguire passo-passo (entra nella funzione, esci, continua).
    • Log: Log.d(TAG, "messaggio"). La lettera indica il livello: d debug, e errore, i info, w warning, v verbose.
    • Logcat: la finestra dove leggi i log. Se l'app crasha mostra lo stack trace con la riga che ha causato l'errore.
    • Profiler: uso di memoria, CPU, rete e GPU. Serve per trovare i memory leak.

    Domande lampo

    Cosa si dichiara nel manifesto?

    Informazioni generali sull'app: permessi, activity, icona, e anche service, receiver e provider.

    Come attivi la modalità sviluppatore?

    Info dispositivo → tocca 7 volte "Versione build", poi in Opzioni sviluppatore attivi Debug USB.

    Quali sono i livelli di Log?

    d (debug), e (errore), i (info), w (warning), v (verbose).

    04

    Layout e misure

    Come si disegna una schermata

    Il layout definisce l'aspetto dell'interfaccia. Si può scrivere in due modi, anche insieme:

    In XML

    • Facile da scrivere
    • Separa la grafica dal codice
    • Però è statico

    Programmatico (nel codice)

    • Dinamico, si adatta a runtime
    • Però devi gestire tutto nel codice

    Le regole base dell'XML

    • Ogni file ha un solo elemento radice (es. un LinearLayout) che contiene gli altri.
    • @+id/testo crea un nuovo ID. @id/testo (senza +) si riferisce a un ID che esiste già. Senza @ il valore è letterale.
    • Gli attributi layout_qualcosa sono parametri per il contenitore padre. layout_width e layout_height sono obbligatori per tutti.
    • match_parent = grande come il padre. wrap_content = grande quanto serve al contenuto.
    • Padding = spazio dentro il bordo. Margin = spazio fuori dal bordo.
    <LinearLayout android:orientation="vertical"
    android:layout_width="match_parent" android:layout_height="match_parent">
  <TextView android:id="@+id/text"
      android:layout_width="wrap_content" android:layout_height="wrap_content"
      android:text="Ciao" />
  <Button android:id="@+id/button"
      android:layout_width="wrap_content" android:layout_height="wrap_content"
      android:text="Premi" />
</LinearLayout>

    px, dp, sp

    • px: pixel reali dello schermo. Da evitare, perché su uno schermo più denso la stessa grafica appare più piccola.
    • dp (density-independent pixel): 1 dp = 1 px su uno schermo da 160 dpi. Si usa per le dimensioni.
    • sp (scale-independent pixel): come dp, ma segue anche la dimensione del font scelta dall'utente. Si usa per i testi.
    Formulapx = dp × (dpi / 160). Esempio: 160 dp sono 160 px a densità 1, 320 px a densità 2, 400 px a densità 2,5.

    Le immagini vanno fornite in più versioni (36, 48, 72, 96 px per densità low, medium, high, extra high). Le icone stanno nella cartella mipmap.

    I contenitori (ViewGroup)

    LayoutCome dispone gli elementi
    FrameLayoutUno sopra l'altro (es. testo sopra un'immagine)
    LinearLayoutIn fila, verticale o orizzontale. layout_weight decide quanto spazio prende ognuno
    RelativeLayoutRispetto al padre o ad altri elementi (layout_below, layout_centerVertical…)
    ConstraintLayoutCon "vincoli" tra elementi. Evita layout annidati troppo profondi (lenti da disegnare). È quello dell'editor grafico
    TableLayoutRighe (TableRow) e colonne
    GridLayoutGriglia con columnCount e rowCount
    ListView / GridViewListe scorrevoli riempite da un Adapter
    Trucco: per dividere lo spazio in parti uguali in un LinearLayout metti width (o height) = "0dp" e layout_weight = "1" a tutti i figli.

    Widget comuni: TextView, Button, EditText, ImageView, CheckBox, RadioButton, Switch. I widget hanno i listener: metodi che "ascoltano" un evento, come onClick per un pulsante.

    Domande lampo

    Differenza tra @+id/nome e @id/nome?

    Con il + crei un nuovo identificatore, senza + ti riferisci a uno già esistente.

    Quando usi sp invece di dp?

    Per le dimensioni dei testi, così rispettano la preferenza dell'utente sulla grandezza del font.

    Quanti px sono 100 dp su uno schermo a 320 dpi?

    100 × 320/160 = 200 px.

    Perché ConstraintLayout invece di tanti layout annidati?

    Una gerarchia profonda richiede più tempo per essere disegnata. Con i vincoli resta piatta.

    05

    ListView e Adapter

    Mostrare liste lunghe

    Una ListView mostra solo gli elementi che entrano nello schermo; gli altri si vedono scorrendo. L'Adapter è il "ponte" che prende i dati da un array e crea le righe man mano che l'utente scorre.

    I 4 passi

    String[] nomi = {"Maria", "Luca", "Anna", ...};                    // 1. i dati
ArrayAdapter<String> ad = new ArrayAdapter<>(this,
        R.layout.list_element, R.id.textViewList, nomi);            // 2. l'adapter
listView = findViewById(R.id.mylistview);                          // 3. il widget
listView.setAdapter(ad);                                           // 4. collegali

listView.setOnItemClickListener((parent, view, position, id) -> {
    String s = listView.getItemAtPosition(position).toString();   // click su una riga
});
    • Lista semplice: ogni riga è una stringa.
    • Lista personalizzata: ogni riga ha il suo layout (nome, foto, telefono…). Serve un CustomAdapter.
    • Click multiplo: per cliccare i singoli pezzi di una riga servono listener separati. Problema: non sai più su quale riga sei. Soluzione: setTag(posizione) sulla view e getTag() nel listener.

    Domande lampo

    A cosa serve l'Adapter?

    Fornisce alla ListView gli elementi da mostrare in base allo scorrimento, prendendoli dai dati (es. un array).

    Con il click multiplo come sai la posizione della riga?

    Salvi la posizione con setTag() e la rileggi con getTag() dentro il listener.

    06

    Ciclo di vita dell'Activity

    Il capitolo più importante

    Un'Activity è una schermata dell'app. Android chiama dei metodi in un ordine preciso mentre l'activity nasce, viene usata e muore:

    onCreate→onStart→onResume→in esecuzione→onPause→onStop→onDestroy
    Cosa succedeMetodi chiamati
    Premi HomeonPause → onStop
    Torni all'apponRestart → onStart → onResume
    Ruoti lo schermoonPause → onStop → onDestroy, poi onCreate → onStart → onResume
    Il punto chiaveQuando ruoti il telefono l'activity viene distrutta e ricreata, quindi le variabili si perdono. È l'errore della Calcolatrice e del Quiz (nel Quiz si può barare ruotando).

    Come salvare lo stato

    @Override
public void onSaveInstanceState(Bundle out) {
    out.putInt("CONTATORE", counter);          // salva
    super.onSaveInstanceState(out);
}

@Override
protected void onCreate(Bundle saved) {
    super.onCreate(saved);
    if (saved != null) counter = saved.getInt("CONTATORE");   // recupera
}
    • onSaveInstanceState + Bundle: il metodo classico, coppie chiave-valore.
    • ViewModel: oggetti che sopravvivono alla distruzione e restano disponibili nella nuova activity.
    • configChanges nel manifesto (es. android:configChanges="orientation"): l'activity non viene distrutta e viene chiamato onConfigurationChanged(). Google lo sconsiglia, va usato solo se le altre strade non bastano.

    Oltre all'orientamento, sono cambi di configurazione anche: dimensione schermo, direzione del testo, tastiera, modalità (auto, TV, orologio…).

    Backstack

    Un'app ha di solito più activity, ognuna con un compito (es. nella posta: lista, lettura, scrittura). Quando ne lanci una nuova, quella corrente va nel backstack (una pila). Il tasto Back toglie quella in cima e torna alla precedente, fino all'Home. Un task è l'insieme di activity con cui l'utente sta interagendo. La activity principale ha nel manifesto l'intent-filter MAIN + LAUNCHER.

    Domande lampo

    Quali metodi vengono chiamati quando premi Home?

    onPause() e onStop().

    Perché ruotando lo schermo si perdono i dati?

    Perché l'activity viene distrutta (onDestroy) e ricreata da zero (onCreate). Bisogna salvare lo stato in onSaveInstanceState o usare un ViewModel.

    Cosa fa il tasto Back?

    Toglie l'activity in cima al backstack e mostra quella precedente.

    Intent

    Il "messaggio" per chiedere di fare qualcosa
    In una fraseUn Intent descrive un'operazione da fare. Serve per lanciare un'activity (startActivity), mandare un broadcast (sendBroadcast) o parlare con un servizio (startService, bindService).

    Le parti di un Intent

    ParteCos'èEsempio
    ActionL'azione da fareACTION_VIEW, ACTION_DIAL, ACTION_PICK
    DataI dati, come URItel:+39…, geo:…, content://contacts/people/1
    CategoryInfo in più sull'azioneCATEGORY_BROWSABLE
    TypeTipo MIME dei dati (di solito dedotto)image/png
    ComponentL'activity precisa da lanciarenew Intent(this, Seconda.class)
    ExtrasDati aggiuntivi chiave-valoreputExtra("CONTATORE", c)
    FlagsCome trattare l'intentFLAG_ACTIVITY_NO_HISTORY

    Esplicito

    • Specifichi il Component
    • "Apri proprio questa activity"

    Implicito

    • Niente Component
    • Android sceglie un'activity adatta in base ad action, type, URI e category, guardando gli intent-filter nei manifesti

    Chiedere un risultato

    Intent i = new Intent(Intent.ACTION_PICK, ContactsContract.Contacts.CONTENT_URI);
startActivityForResult(i, REQUEST_CODE);       // "scegli un contatto e dimmi quale"

@Override
protected void onActivityResult(int req, int res, Intent data) {
    if (req == REQUEST_CODE && res == Activity.RESULT_OK) { /* usa data */ }
}

    L'app VisualizzaMappa fa proprio così: prende un indirizzo dalla rubrica (serve il permesso) e lo apre in Google Maps, usando activity di altre app.

    Domande lampo

    Differenza tra intent esplicito e implicito?

    Esplicito: indichi l'activity precisa. Implicito: indichi cosa vuoi fare e Android trova chi può farlo.

    A cosa serve REQUEST_CODE?

    A riconoscere, in onActivityResult, a quale richiesta corrisponde il risultato.

    Come passi un numero a un'altra activity?

    intent.putExtra("CHIAVE", valore) prima di lanciarla; dall'altra parte lo leggi dagli extras dell'intent.

    08

    Permessi

    Chiedere il consenso all'utente

    I permessi proteggono i dati dell'utente (contatti), i servizi che costano (SMS, chiamate, Internet) e le risorse di sistema (fotocamera, GPS). Sono stringhe tipo android.permission.CAMERA e vanno sempre dichiarati nel manifesto:

    <uses-permission android:name="android.permission.CAMERA" />

    Normali

    • Concessi in automatico
    • Es. INTERNET, VIBRATE, BLUETOOTH, WAKE_LOCK, SET_ALARM

    Pericolosi

    • L'utente deve approvarli
    • Es. CAMERA, READ_CONTACTS, ACCESS_FINE_LOCATION, SEND_SMS, RECORD_AUDIO
    • API < 23: si accettano all'installazione.
    • API ≥ 23: si chiedono mentre l'app gira. Alla seconda richiesta l'utente può rendere la risposta definitiva.
    • API ≥ 30: si può dare il permesso "solo questa volta".
    • I pericolosi sono divisi in gruppi (CONTACTS, LOCATION, SMS…). Se hai già un permesso di un gruppo, gli altri dello stesso gruppo vengono concessi senza chiedere.
    L'utente può togliere un permesso dalle Impostazioni quando vuole. Quindi nel codice controlla SEMPRE prima di usarlo.

    Lo schema da ricordare

    if (ContextCompat.checkSelfPermission(ctx, Manifest.permission.CAMERA)
        == PackageManager.PERMISSION_GRANTED) {
    usaLaFotocamera();                         // 1. ce l'ho: procedo
} else if (shouldShowRequestPermissionRationale(...)) {
    spiegaPerche();                            // 2. spiego all'utente a cosa serve
} else {
    requestPermissionLauncher.launch(Manifest.permission.CAMERA);   // 3. lo chiedo
}

    Domande lampo

    Basta dichiarare un permesso pericoloso nel manifesto?

    No. Da API 23 va anche chiesto a runtime, e bisogna controllare con checkSelfPermission prima di usarlo.

    INTERNET è normale o pericoloso?

    Normale: va nel manifesto ma viene concesso senza chiedere.

    09

    Thread e AsyncTask

    Fare lavori lunghi senza bloccare l'app

    Un thread è un flusso di esecuzione parallelo dentro un processo. Ogni thread ha il suo program counter e il suo stack, ma condivide con gli altri la memoria (heap).

    • Si crea un oggetto Thread con dentro un Runnable (che ha il metodo run()) e si chiama start(), che a sua volta esegue run().
    • Altri metodi: sleep(ms), wait(), notify().
    Regola d'oroSolo il main thread (UI thread) può toccare l'interfaccia. Un thread in background che vuole aggiornare la UI deve usare runOnUiThread(Runnable) oppure view.post(Runnable). È la differenza tra le app ThreadNo e ThreadSi.

    AsyncTask

    Classe che semplifica il dialogo tra thread in background e main thread. È generica: AsyncTask<Params, Progress, Result> (tipo dell'input, tipo dell'avanzamento, tipo del risultato).

    MetodoDove giraQuando
    onPreExecute()mainPrima di iniziare (setup)
    doInBackground(Params…)backgroundIl lavoro vero. Restituisce un Result. Può chiamare publishProgress()
    onProgressUpdate(Progress…)mainDopo ogni publishProgress (es. aggiorna la barra)
    onPostExecute(Result)mainAlla fine, riceve il risultato
    AsyncTask oggi è deprecato da Google (da API 30), ma è nelle slide: per l'esame va saputo.

    Domande lampo

    Un thread in background può cambiare il testo di una TextView?

    Non direttamente. Deve passare dal main thread con runOnUiThread() o view.post().

    Quale metodo dell'AsyncTask gira in background?

    Solo doInBackground(). Gli altri tre girano nel main thread.

    10

    Frammenti (Fragments)

    Pezzi di interfaccia riutilizzabili

    Un frammento è una porzione di interfaccia, una specie di sotto-activity. Vive sempre dentro un'activity e il suo ciclo di vita è legato a quello dell'activity (se l'activity va in pausa, ci vanno anche i frammenti).

    Perché esistonoPer adattarsi allo schermo. Esempio: app di notizie con un frammento lista titoli e un frammento articolo. Su tablet o in orizzontale li vedi affiancati; su telefono in verticale ne vedi uno alla volta.

    Metodi da implementare

    • onCreate(): inizializzazione, ma non il layout.
    • onCreateView(): crea il layout con inflater.inflate(...) e restituisce la View. È l'equivalente di setContentView.
    • onPause(): primo metodo chiamato quando il frammento se ne va. Qui salvi le modifiche.

    Inserirli

    Statico: con il tag <fragment> nel layout XML. Dinamico: a runtime, con una transazione:

    FragmentTransaction ft = getFragmentManager().beginTransaction();
ft.add(R.id.fragment_container, new ExampleFragment());   // anche remove, replace
ft.addToBackStack(null);                                  // facoltativo, vedi sotto
ft.commit();
    • Il backstack gestisce da solo solo le activity. Se non chiami addToBackStack(), premendo Back si "saltano" i cambi fatti con i frammenti.
    • Comunicazione: i frammenti non parlano direttamente tra loro (si perde riusabilità). Il frammento A definisce un'interfaccia; l'activity la implementa e passa il dato al frammento B (in orizzontale) o apre una nuova activity (in verticale).

    Domande lampo

    In quale metodo del frammento si crea il layout?

    onCreateView(), facendo l'inflate di un file di layout e restituendo la View.

    Come comunicano due frammenti?

    Passando per l'activity che li ospita, tramite un'interfaccia di callback che l'activity implementa.

    11

    Networking

    Parlare con un server
    • InetAddress: gestisce gli indirizzi IP. InetAddress.getByName("www.server.com").
    • Socket: il canale con il server. new Socket(indirizzo, porta). Per scrivere usi un PrintWriter sull'output stream, per leggere un BufferedReader sull'input stream (readLine()).
    • HttpURLConnection: per le pagine web. openConnection(), poi getInputStream() e leggi come prima.
    • JSoup: libreria esterna per leggere l'HTML e estrarne pezzi (Jsoup.connect(url).get(), getElementById, select). Il .jar va nella cartella libs e si aggiunge la dipendenza in build.gradle.
    Dall'emulatore, il "localhost" del tuo PC è l'indirizzo 10.0.2.2
    • Da API 28 le connessioni http in chiaro sono bloccate ("Cleartext not permitted"): usa https o abilitale nella configurazione di sicurezza.
    • Le operazioni di rete sono lunghe: si fanno in un thread separato (vedi capitolo 09). Serve il permesso INTERNET.

    Domande lampo

    Che indirizzo usa l'emulatore per raggiungere il PC?

    10.0.2.2

    Cosa significa l'errore "Cleartext not permitted"?

    Che da API 28 le connessioni http non cifrate sono disabilitate di default.

    12

    Salvare i dati

    File, preferenze, database SQL

    Dove stanno i dati

    • Spazio privato: ogni app ha la sua cartella, accessibile solo a lei. Se disinstalli l'app viene cancellata.
    • Spazio pubblico: file condivisi con altre app (foto, musica, documenti).
    • Attenzione: "External" non vuol dire SD card. Vuol dire fuori dallo spazio privato; può stare nella memoria interna (/storage/emulated/0/) o sulla SD (/storage/XXXX-XXXX/).
    Metodo (Context)Percorso
    getFilesDir()/data/user/0/<package>/files/
    getCacheDir()/data/user/0/<package>/cache/
    getDatabasePath(n)/data/user/0/<package>/databases/n
    getExternalFilesDir()/storage/emulated/0/Android/data/<package>/files/

    Lo 0 nel percorso è l'ID dell'utente principale.

    Storage e permessi nel tempo

    • API ≤ 28: READ_/WRITE_EXTERNAL_STORAGE danno accesso a tutto.
    • API 29+: le app sono "sandboxed" anche fuori. Per i media condivisi si usa MediaStore (un Content Provider con un database SQL di indici), per gli altri file SAF.
    • API 30+: WRITE ignorato; MANAGE_EXTERNAL_STORAGE per file manager e backup (va giustificato su Google Play).
    • API 33+: READ_MEDIA_IMAGES, _VIDEO, _AUDIO.

    SharedPreferences

    Piccoli dati in coppie chiave-valore (es. impostazioni). Per leggere usi get; per scrivere serve un Editor:

    SharedPreferences p = getSharedPreferences("file", MODE_PRIVATE);
boolean v = p.getBoolean("KEY", false);       // leggi
SharedPreferences.Editor e = p.edit();
e.putBoolean("KEY", true);
e.commit();                                   // senza commit non salva!

    File

    FileOutputStream fos = openFileOutput("hello_file", Context.MODE_PRIVATE);
fos.write("hello world!".getBytes());
fos.close();                                  // per leggere: openFileInput, read, close

    Modi: MODE_PRIVATE, MODE_APPEND. Un file statico si mette in res/raw e si legge con openRawResource(R.raw.nome). Per i file temporanei c'è la cache (max consigliato 1 MB; Android la svuota se serve spazio).

    Mini ripasso SQL

    ComandoFa
    CREATE / ALTER / DROPCrea / modifica / cancella una tabella
    SELECTLegge righe: SELECT NAME FROM CUSTOMERS WHERE SALARY > 5000 ORDER BY NAME
    INSERTAggiunge una riga
    UPDATEModifica righe (WHERE sceglie quali; senza WHERE le cambia tutte!)
    DELETECancella righe

    La chiave primaria è la colonna che identifica in modo unico ogni riga.

    SQLite in Android

    • Crei una sottoclasse di SQLiteOpenHelper e nel suo onCreate() esegui la CREATE TABLE con db.execSQL(). Va riscritto anche onUpgrade().
    • db = helper.getWritableDatabase() ti dà il database.
    • Per inserire metti i valori in un ContentValues e chiami db.insert(tabella, null, valori). Ci sono anche db.update() e db.delete().
    • db.query(...) restituisce un Cursor: lo scorri con moveToFirst() e moveToNext(), e leggi con getInt()/getString() + getColumnIndex().

    Domande lampo

    "External storage" vuol dire SD card?

    No: vuol dire fuori dallo spazio privato dell'app. Può essere memoria interna o SD.

    Come salvi un booleano nelle SharedPreferences?

    Prendi l'Editor con edit(), usi putBoolean(chiave, valore) e poi commit().

    Cosa restituisce db.query()?

    Un Cursor, che si scorre con moveToFirst/moveToNext per leggere i record.

    Grafica e custom view

    Disegnare, animare, creare widget propri
    • Si disegna in una View (grafica semplice, statica) o in un Canvas (grafica complessa, aggiornata spesso).
    • Drawable = qualcosa che si può disegnare: ShapeDrawable (forma), BitmapDrawable (immagine), ColorDrawable (colore). Si mette nella view da XML o con setImageDrawable().
    • Animazioni definite in XML: rotazione, traslazione, ridimensionamento, trasparenza. La classe Animation le legge e le applica a un'ImageView.

    Come Android disegna le view: 3 fasi

    Le view formano un albero. Per disegnarlo, Android lo visita tre volte dall'alto in basso:

    1 · Measure→2 · Layout→3 · Draw
    • onMeasure: il padre chiede ai figli quanto vorrebbero essere grandi (LayoutParams: un numero, MATCH_PARENT o WRAP_CONTENT) e comunica i vincoli con MeasureSpec. Alla fine ogni view deve aver fissato setMeasuredDimension().
    • onLayout: il padre decide posizione e dimensione reali di ogni figlio.
    • onDraw(Canvas): ogni view si disegna, usando un oggetto Paint e i metodi del Canvas.
    MeasureSpecSignifica
    UNSPECIFIED"Quanto spazio vorresti?"
    EXACTLY"Sarai grande esattamente così"
    AT_MOST"Al massimo così"
    Da non confondereinvalidate() ridisegna solo quella view (richiama onDraw). requestLayout() rifà tutto il processo (measure, layout, draw) sull'albero.

    Domande lampo

    Quali sono le tre fasi del disegno?

    Misura (onMeasure), posizionamento (onLayout), disegno (onDraw).

    invalidate() o requestLayout() se cambia solo il colore?

    invalidate(): basta ridisegnare, la dimensione non cambia.

    Multitouch e gesti

    Dita sullo schermo

    Un tocco è un MotionEvent. Ogni dito è un pointer, con un ID che resta uguale finché il dito è giù. L'indice invece può cambiare da un evento all'altro: non confonderli.

    ActionQuando
    ACTION_DOWNIl primo dito tocca
    ACTION_POINTER_DOWNUn altro dito tocca (non il primo)
    ACTION_MOVEUn dito si muove
    ACTION_POINTER_UPSi alza un dito, ma ne restano altri
    ACTION_UPSi alza l'ultimo dito

    Metodi utili: getActionMasked(), getPointerCount(), getActionIndex(), getPointerId(i), getX(i), getY(i), findPointerIndex(id).

    • La view riceve l'evento in onTouchEvent(); un listener esterno con setOnTouchListener() riceve onTouch() prima della view.
    • Entrambi restituiscono un booleano: true = evento consumato. Se restituisci false non riceverai i MOVE e UP successivi di quel gesto.
    • GestureDetector riconosce gesti già pronti: tocco singolo, doppio tocco, fling (scorrimento veloce).
    • ViewFlipper (sottoclasse di ViewAnimator) mostra una view alla volta con animazione: showNext(), showPrevious().

    Domande lampo

    Secondo dito che tocca: che action?

    ACTION_POINTER_DOWN.

    Cosa succede se onTouch restituisce false su ACTION_DOWN?

    Dici che non ti interessa: non riceverai più gli eventi successivi di quel gesto.

    MediaPlayer e audio focus

    Suonare audio e video
    MediaPlayer mp = MediaPlayer.create(context, R.raw.brano);  // create() fa già prepare()
mp.start();   mp.pause();   mp.stop();
mp.release(); mp = null;                                     // libera la risorsa!
    • Da URL: new MediaPlayer(), setDataSource(url), prepare(), start(). Per URL esterni meglio prepareAsync() e far partire in onPrepared(), perché il caricamento può essere lungo.
    • AudioManager controlla sorgenti e volume.

    Audio focus

    L'uscita audio è una sola. Per non sovrapporsi (es. musica che copre il suono di un messaggio) un'app chiede il focus prima di suonare, con un AudioFocusRequest (tipo di audio + listener).

    Richieste

    • GAIN: normale
    • GAIN_TRANSIENT: uso breve
    • …_MAY_DUCK: gli altri continuano a volume basso
    • …_EXCLUSIVE: silenzio per gli altri

    Cosa fare quando cambia

    • LOSS: fermati
    • LOSS_TRANSIENT: pausa
    • LOSS_TRANSIENT_CAN_DUCK: abbassa il volume
    • GAIN: riprendi

    Domande lampo

    Serve chiamare prepare() dopo MediaPlayer.create()?

    No, create() lo fa già.

    Cosa fa un'app quando riceve AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK?

    Abbassa il volume e continua.

    Sensori

    Movimento, ambiente, posizione

    Tre famiglie: di movimento (accelerometro, giroscopio), di ambiente (temperatura, pressione, umidità, luce), di posizione (magnetometro). Danno dati grezzi. Alcuni sono hardware, altri software (calcolati da altri sensori).

    Gli assi x, y, z sono fissi rispetto al dispositivo: se lo ruoti, cambiano i valori letti. L'accelerometro misura in m/s² e include la gravità.

    public class SensorActivity extends Activity implements SensorEventListener {
  onCreate:   sm = (SensorManager) getSystemService(SENSOR_SERVICE);
              luce = sm.getDefaultSensor(Sensor.TYPE_LIGHT);   // null se non c'è
  onResume:   sm.registerListener(this, luce, SensorManager.SENSOR_DELAY_NORMAL);
  onPause:    sm.unregisterListener(this);
  onSensorChanged(SensorEvent e):  float lux = e.values[0];
  onAccuracyChanged(...)
}
    Registra in onResume e togli in onPause, altrimenti il sensore resta acceso e consuma batteria.

    Velocità di lettura: NORMAL (0,2 s), UI (0,06 s), GAME (0,02 s), FASTEST (0 s).

    Domande lampo

    Come sai se il telefono ha un certo sensore?

    getDefaultSensor(tipo) restituisce null se non c'è.

    Perché unregisterListener in onPause?

    Per non consumare batteria quando l'activity non è visibile.

    Notifiche

    Avvisare l'utente fuori dall'app
    • Toast: messaggio breve che scompare da solo.
    • Dialog: finestra che chiede un'interazione.
    • Notifiche: icona nella barra di stato, pallino sull'icona dell'app, testo nel cassetto delle notifiche. Restano finché l'utente le cancella o l'app le revoca.
    • API 21: notifiche heads-up (a comparsa) per quelle urgenti.
    • API 26: canali. Ogni notifica deve stare in un canale, altrimenti non compare. L'utente può disattivare singoli canali.
    • API 33: permesso POST_NOTIFICATIONS, nel manifesto e a runtime.
    NotificationChannel ch = new NotificationChannel(id, nome, importanza);
notificationManager.createNotificationChannel(ch);

NotificationCompat.Builder nb = new NotificationCompat.Builder(this, id)
    .setSmallIcon(R.drawable.ancora)
    .setContentIntent(pendingIntent);          // cosa si apre al tocco
notificationManager.notify(notification_id, nb.build());
    Da API 26 l'icona deve avere sfondo trasparente e un solo colore, se no esce un quadrato bianco.

    Domande lampo

    Perché una notifica potrebbe non comparire su Android 8+?

    Perché non è assegnata a un canale.

    Cosa serve in più su Android 13?

    Il permesso POST_NOTIFICATIONS, chiesto anche a runtime.

    Alarms

    Eseguire codice a un'ora precisa

    Un alarm lancia un intent in un momento stabilito, anche se l'app è chiusa o il telefono dorme. Resta attivo finché non viene cancellato o il telefono si spegne. Si usa l'AlarmManager.

    Imprecisi (inexact)

    • Il sistema può spostarli per risparmiare batteria
    • Da API 31 partono entro un'ora
    • set(), setInexactRepeating(), setAndAllowWhileIdle()

    Precisi (exact)

    • All'ora esatta
    • Da API 31 serve SCHEDULE_EXACT_ALARM o USE_EXACT_ALARM
    • setExact(), setExactAndAllowWhileIdle(), setAlarmClock() (sempre garantito)
    • Doze mode: telefono non in carica, schermo spento, fermo, niente in esecuzione. Gli alarm vengono ritardati e la rete in background è bloccata.
    • App standby: per le app non usate da tempo. Attività in background sospese, alarm ritardati.
    • Da API 29 un alarm non può riportare l'app in primo piano da solo: si mostra una notifica e sarà l'utente a toccarla.

    Domande lampo

    Quale metodo garantisce sempre l'orario?

    setAlarmClock().

    Cos'è la Doze mode?

    Uno stato di risparmio batteria (schermo spento, non in carica, fermo) in cui alarm e rete in background vengono ritardati.

    Broadcast

    Messaggi per tutti

    Le 4 componenti fondamentali di Android sono Activity, Broadcast, Content Provider, Service. Le ultime tre servono in casi particolari.

    In una fraseUn broadcast è un messaggio globale (un Intent) che chiunque sia interessato può ricevere. Chi lo manda usa sendBroadcast(), chi lo riceve è un BroadcastReceiver con il metodo onReceive().
    • Di sistema: eventi globali come BOOT_COMPLETED, AIRPLANE_MODE, BATTERY_LOW, TIME_TICK (ogni minuto), SMS_RECEIVED.
    • Custom: definiti dalle app. Impliciti (un'azione, es. "it.unisa.…BROADCAST_PERSONALIZZATO") o espliciti (con il component, li riceve solo quel receiver).

    Statico (nel manifesto)

    • <receiver> con <intent-filter>
    • android:exported obbligatorio
    • Da API 26 solo per i custom e pochi di sistema (BOOT_COMPLETED, POWER_CONNECTED…)

    Dinamico (nel codice)

    • registerReceiver(receiver, filtro)
    • Va tolto con unregisterReceiver()
    • Coppie coerenti: onCreate/onDestroy oppure onResume/onPause
    • sendBroadcast(intent, permesso): arriva solo a chi ha quel permesso.
    • I broadcast locali (LocalBroadcastManager) sono obsoleti; oggi si usano ViewModel, LiveData, WorkManager.
    • Non togliere il receiver in onSaveInstanceState: con il tasto Back non viene chiamato.

    Domande lampo

    Differenza tra receiver statico e dinamico?

    Statico: dichiarato nel manifesto, registrato all'installazione/boot. Dinamico: registrato nel codice con registerReceiver().

    Quale metodo implementa un BroadcastReceiver?

    onReceive(Context, Intent).

    Content Provider

    Condividere dati tra app

    Un Content Provider espone i dati di un database ad altre app. Esempi già pronti: rubrica, registro chiamate, cronologia del browser, file multimediali. Ci si accede con un ContentResolver, con comandi simili a SQL (query, insert, update, delete) più le notifiche sui cambiamenti.

    L'URIcontent://authority/path/id
    authority = quale provider · path = quale tabella · id = quale record (chiave primaria). Senza id indichi tutta la tabella.

    Esempio: content://com.android.contacts/contacts/ è tutta la tabella dei contatti.

    Crearne uno

    • Una classe che estende ContentProvider e implementa query(uri, projection, selection, args, sortOrder), che restituisce un Cursor.
    • L'authority si dichiara nel manifesto con <provider android:authorities="…" android:exported="true"/>.
    • Da API 30 l'app client deve dichiarare nel suo manifesto i provider che usa, dentro <queries>.
    • Per leggere la rubrica serve READ_CONTACTS.

    Domande lampo

    Cosa indicano authority e path in un URI?

    Authority il provider, path la tabella.

    Cosa cambia per il client da API 30?

    Deve dichiarare nel manifesto, in <queries>, i Content Provider a cui vuole accedere.

    Service

    Lavoro in background senza interfaccia

    Un Service fa operazioni lunghe senza interfaccia: scaricare un file, sincronizzare con un server, suonare musica. Può continuare a girare a lungo, ma il sistema può fermarlo se servono risorse.

    Trabocchetto classico: di default un Service gira nel main thread dell'app, non in un thread separato!

    Unbound (avviato)

    • startService() / stopService()
    • Vive da solo, anche se chi l'ha lanciato termina
    • Callback: onStartCommand()

    Bound (agganciato)

    • bindService()
    • Le componenti diventano "client" e ci comunicano
    • Vive finché c'è almeno un client agganciato
    • Callback: onBind()

    Uno stesso service può funzionare in entrambi i modi. Va dichiarato nel manifesto con <service android:name=".MyService"/>.

    Domande lampo

    Quando muore un service bound?

    Quando non ci sono più client agganciati.

    Un service gira in un thread separato?

    No, per default gira nel main thread, a meno che non lo specifichi tu.
