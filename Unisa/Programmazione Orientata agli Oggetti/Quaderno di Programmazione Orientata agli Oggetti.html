    Java: introduzione

    Da dove viene Java, perché è portabile, compilazione e interpretazione, le caratteristiche del linguaggio.

    Da C++ a Java

    C++ è un linguaggio general-purpose ibrido: supporta più paradigmi insieme, cioè la programmazione procedurale (è un “C migliore”), quella orientata agli oggetti e quella generica.

    Java nasce nel 1995 alla Sun Microsystems (James Gosling) come evoluzione del C++. Offre meccanismi per applicazioni distribuite su rete, facili da integrare con il web e i browser, e una vasta libreria (grafica, rete, basi di dati…).

    Le caratteristiche di Java

    CaratteristicaChe cosa vuol dire
    Semplice e orientato agli oggettiSintassi simile a C/C++ ma senza i costrutti “pericolosi”: niente aritmetica dei puntatori, niente (de)allocazione esplicita della memoria, niente aliasing, struct, typedef, preprocessore (#define), interrupt, array senza controllo dei limiti (buffer overflow). In più aggiunge la garbage collection automatica.
    InterpretatoIl compilatore produce bytecode per la Java Virtual Machine, che poi viene interpretato.
    Architetturalmente neutro e portabileIl bytecode non dipende dall’hardware (formato ANDF, Architecture Neutral Distribution Format): gira ovunque ci sia una JVM. Il compilatore è scritto in Java, l’ambiente run-time in ANSI C con interfacce POSIX: nessuna dipendenza dall’implementazione.
    RobustoControlli estesi a compile-time e a run-time (es. type checking); niente puntatori espliciti, garbage collection, array e stringhe “veri”, verifica del bytecode al caricamento.
    DistribuitoPensato per la rete: il run-time ha funzioni di rete di basso (TCP/IP) e alto livello (HTTP).
    SicuroIl bytecode viene verificato prima dell’interpretazione; gli indirizzamenti alla memoria sono risolti sotto il controllo dell’interprete.
    DinamicoLe classi vengono caricate e collegate quando servono (anche dalla rete).
    ConcorrenteIl multithreading fa parte del linguaggio: applicazioni interattive più reattive.
    RiccoStandard Library: supporto al linguaggio, utility, I/O, networking, AWT.

    Platform dependent e platform independent

    C e C++

    Il codice va compilato su ogni piattaforma su cui deve girare: l’eseguibile è in linguaggio macchina di quel processore.

    Java

    javac traduce il sorgente .java in bytecode .class, il linguaggio di un processore virtuale. Ogni JVM ha un interprete che traduce il bytecode nel linguaggio macchina locale. Vantaggio: portabilità. Svantaggio: velocità.

    Sorgente .java→ javac →Bytecode .class→Class loader→Verifica del bytecode→Interprete (JVM)→Hardware

    Esempio dalle slide: il ciclo for (i = 0; i < 100; i++); diventa una sequenza di istruzioni bytecode come iconst_0, istore_1, iinc, bipush 100, if_icmplt, return.

    Compilatore e interprete

    Per sviluppare servono editor, compilatore e/o interprete.

    Compilazione

    Traduce l’intero programma in linguaggio macchina prima di eseguirlo. Se ci sono più sorgenti, si compilano separatamente e un linker li collega; il loader li carica.

    Interpretazione

    È il ciclo fetch-execute portato ad alto livello: prende un’istruzione alla volta, la traduce in una o più istruzioni macchina, le esegue subito, passa alla successiva.

    • L’interpretazione è meno efficiente a run-time (più memoria, overhead dell’interprete che deve analizzare ogni istruzione).
    • L’interpretazione rende più facile trovare le cause degli errori a run-time, perché resta il legame con il sorgente.
    • La compilazione può fare ottimizzazioni, perché vede tutto il programma.

    Cosa serve

    Il JDK (Java Development Kit, comprende anche il JRE), la documentazione Javadoc e un editor o IDE (Eclipse, JCreator, JBuilder…). Il sistema operativo può essere qualunque.

    Da non confondereJava è compilato e interpretato: javac compila in bytecode, la JVM lo interpreta. “Portabile” non vuol dire che il bytecode sia codice macchina: è codice per un processore virtuale.

    Domande lampo

    Che cosa produce javac?

    Bytecode (file .class) per la Java Virtual Machine, non linguaggio macchina.

    Vantaggio e svantaggio del bytecode interpretato?

    Vantaggio: portabilità. Svantaggio: velocità.

    Perché Java è “sicuro”?

    Il bytecode viene verificato prima dell’interpretazione e gli accessi alla memoria sono risolti dall’interprete.

    Quali costrutti di C/C++ elimina Java?

    Aritmetica dei puntatori, deallocazione esplicita, struct, typedef, #define, array senza controllo dei limiti.

    Che cosa vuol dire “dinamico”?

    Le classi vengono caricate e collegate a run-time, quando servono.

    Classi e oggetti

    Tipo di dato astratto, attributi, metodi, variabili locali, passaggio dei parametri, varargs, il main.
    DefinizioneUna classe realizza un tipo di dato astratto (ADT): ha un nome e contiene due tipi di membri, gli attributi (i dati) e i metodi (le funzioni che operano sui dati). Un oggetto è un’istanza della classe, creata con new.

    Esempio: un’automobile ha dati (targa, colore, velocità, livello benzina) e funzioni (avviati, fermati, accelera).

    La classe in Java

    • È identificata da un nome che, per una classe public, deve coincidere con il nome del file (Prova.java contiene class Prova).
    • Il corpo è tra parentesi graffe e contiene dichiarazioni e istruzioni.
    • Il nome può essere preceduto da modificatori: public, private, static…
    public class Auto {
    public int cilindri = 4;     // inizializzato esplicitamente
    public int speed = 0;
    public String targa;         // inizializzato automaticamente a null

    public int getSpeed() { return speed; }
    public void setSpeed(int s) { speed = s; }
    public void accelera() { speed++; }
}

Auto panda = new Auto();   // creazione dell'oggetto
panda.setSpeed(100);
int s = panda.getSpeed();   // il tipo restituito deve essere compatibile con s

    Una classe vuota non serve a niente: bisogna aggiungere attributi e metodi. Con soli attributi si può solo leggerli e modificarli (panda.speed = 10;).

    Attributi e metodi

    Sintassi di un attributo: [modificatore] Tipo nome [= valore];. Un metodo ha un nome, un tipo di ritorno, una lista di parametri e un corpo tra graffe.

    La slide dice che l’attributo senza modificatore è public per default. In realtà, come si vede nel cap. 14, senza modificatore l’accesso è package (“friendly”): visibile solo nel package.

    return ha due funzioni: termina il metodo e restituisce il valore di ritorno. In un metodo void si può scrivere return; o niente.

    public boolean flag() { return true; }
public float naturalLogBase() { return 2.718f; }
public void nothing() { return; }
public void nothing2() {}

    Variabili locali

    Le variabili locali a un metodo:

    • sono visibili solo nel corpo del metodo;
    • sono allocate nello stack alla chiamata e deallocate all’uscita;
    • non vengono inizializzate automaticamente (a differenza degli attributi di una classe).
    int i;
if (cond) { i = 55; }
i++;     // errore di compilazione: i potrebbe non essere inizializzata

    Nell’esempio foo() chiama multiply(x, y): nello stack compare prima il record di foo con x = 5 e y = 12, poi quello di multiply con num1, num2 e result; all’uscita di multiply il suo record sparisce.

    Passaggio dei parametri: tutto per valore

    • La lista dei parametri specifica tipo e ordine; il compilatore dà errore se il tipo passato non corrisponde.
    • Dei tipi semplici (int, boolean, char…) viene passato il valore.
    • Degli oggetti (array, stringhe, oggetti dell’utente) viene passato il riferimento, sempre per valore.
    Domanda tipicaCome si ottiene un parametro di uscita? Solo con un oggetto: il metodo riceve una copia del riferimento e può modificare lo stato dell’oggetto puntato. Non può invece far puntare la variabile del chiamante a un altro oggetto.

    Varargs

    Da Java 1.5 un metodo può accettare zero o più parametri di un tipo:

    public static int somma(int... args) {
    int sum = 0;
    for (int arg : args) sum += arg;
    return sum;
}

    Internamente viene creato un array con gli argomenti. Ogni chiamata quindi alloca e inizializza un array: se il numero di parametri è prevedibile conviene l’overloading.

    Hello World e il main

    class Hello {
    public static void main(String args[]) {
        System.out.println("Hello World!");
    }
}
    ParolaPerché c’è
    publicRende il main visibile alle altre classi e al comando java.
    staticAssocia il main alla classe, non alle istanze: si può chiamare senza creare oggetti.
    voidIl main non restituisce nulla.
    String args[]Gli argomenti passati da shell: java Hello arg1 … argn.
    System.out.printlnChiama il metodo println dell’oggetto out della classe System, che scrive su stdout.

    Esempio: copiare un riferimento

    class Contatore {
    int cont = 0;
    public void incr() { cont++; }
    public static void main(String args[]) {
        Contatore a = new Contatore();
        Contatore b = new Contatore();
        a.incr();
        System.out.println(a.cont);   // 1
        System.out.println(b.cont);   // 0
        b = a;                        // copia i riferimenti
        System.out.println(a.cont);   // 1
        System.out.println(b.cont);   // 1
        b.incr();
        System.out.println(a.cont);   // 2
        System.out.println(b.cont);   // 2
    }
}

    Dopo b = a le due variabili puntano allo stesso oggetto: l’oggetto creato prima per b non è più raggiungibile e verrà raccolto dal garbage collector.

    Domande lampo

    Le variabili locali sono inizializzate a 0?

    No: vanno inizializzate prima dell’uso, altrimenti errore di compilazione. Gli attributi invece sì.

    In Java il passaggio è per valore o per riferimento?

    Sempre per valore: dei tipi semplici si copia il valore, degli oggetti si copia il riferimento.

    Perché il main è static?

    Perché deve poter partire senza che esista un oggetto della classe.

    Cosa crea Java per un metodo con varargs?

    Un array con gli argomenti, a ogni chiamata.

    A cosa serve return?

    A terminare il metodo e a restituire il valore di ritorno.

    05

    Classi composte

    Classi fatte di altri oggetti, struttura di un’applicazione, compilazione, stack e heap, classi interne.

    Una classe può essere costituita da altri oggetti: un’automobile è fatta di ruote, carrozzeria, motore.

    Struttura di un’applicazione

    • Il sorgente è fatto di uno o più file, le unità di compilazione.
    • Ogni file contiene una o più classi (o interfacce), al più una dichiarata public.
    • Il file deve chiamarsi come la sua classe public, con estensione .java.
    • javac a.java produce un file .class per ogni classe (a.class, b.class…).
    • java a args esegue: la classe a deve avere un metodo public static di nome main.
    public class Test {
    public static void main(String args[]) {
        Auto myCar = new Auto();
        myCar.setSpeed(10);
        System.out.println("speed=" + myCar.getSpeed());
    }
}
class Auto {
    int cilindri = 4;
    int speed = 0;
    public int getSpeed() { return speed; }
    public void setSpeed(int s) { speed = s; }
}

    Compilazione ed esecuzione

    Le classi vanno compilate secondo l’ordine di dipendenza: la classe che dipende dalle altre va compilata per ultima. Esecuzione di ShirtTest:

    java ShirtTest→caricata ShirtTest→esegue il main→caricata Shirt→new Shirt()→modifica colorCode→fine

    Stack e heap

    Stack

    Contiene le variabili locali e i parametri dei metodi, compresi i riferimenti agli oggetti.

    Heap

    Contiene gli oggetti creati con new, con i loro attributi.

    Se a un riferimento si assegna un altro oggetto, il primo oggetto resta nell’heap senza riferimenti. Nelle slide: in C++ non andrebbe mai fatto, perché si perde ogni riferimento e quindi la possibilità di fare delete; in Java ci pensa il garbage collector.

    Classi interne

    Una classe interna è definita dentro un’altra: serve a raggruppare classi logicamente correlate e a controllarne la visibilità.

    public class Document {
    private String title = "Titolo";
    class Destination {
        private String label;
        Destination(String whereTo) { label = whereTo; }
        String readLabel() { return label; }
        String returnTitolo() { return Document.this.title; }
    }
    public void ship(String dest) {
        Destination d = new Destination(dest);
        System.out.println(d.readLabel());
    }
    public static void main(String[] args) {
        Document doc = new Document();
        Document.Destination dec = doc.new Destination("Tanzania");
        String str = dec.returnTitolo();
    }
}
    • La classe interna ha completa visibilità di attributi e metodi della classe esterna, anche privati (Document.this.title).
    • Un’istanza della classe interna si ottiene solo a partire da un’istanza della classe esterna: doc.new Destination(...).
    • Fuori da Document (o nei metodi statici) il nome è Document.Destination.
    • Con private, protected, public si disciplina la visibilità: una classe interna private non si può istanziare dall’esterno.

    Domande lampo

    Quante classi public può avere un file?

    Al più una, e il file deve avere il suo nome.

    Quanti .class produce un file con tre classi?

    Tre, uno per classe.

    Dove stanno gli oggetti e dove i riferimenti locali?

    Oggetti nell’heap, variabili locali (riferimenti compresi) nello stack.

    Come si crea un oggetto di una classe interna dal main?

    A partire da un oggetto della classe esterna: doc.new Destination("…").

    Modificatori e information hiding

    Ruolo cliente e servente, specifica e implementazione, public, private, get e set.

    Una classe può avere un doppio ruolo:

    Cliente

    Usa le risorse messe a disposizione da altre classi.

    Servente

    È usata da altre classi o da un programma utente.

    Esempio: l’automobile ha un’interfaccia pubblica (volante, blocchetto di accensione, acceleratore: “ciò che l’auto può fare”) e un’implementazione privata (meccanica dello sterzo, avviamento, alimentazione: “come lo fa”).

    Specifica della classeÈ l’interfaccia della classe: descrive le risorse offerte agli utenti e le regole sintattiche per usarle. È separata dall’implementazione, così si può usare la classe senza conoscerne i dettagli. La scrive lo sviluppatore della classe.
    public class C {
    // public: prototipi delle funzioni membro (la specifica)
    public T1 f1(...);
    public T2 f2(...);
    // private: struttura dati
    private int i;
    private char c;
}

    public e private

    public class Customer {
    private String name;
    public void setName(String customerName) {
        name = customerName.toUpperCase();
    }
}
Customer cust = new Customer();
cust.setName("John Phillips");   // OK
cust.name = "Jack Phillips";     // errore: name è private

    Con public l’assegnamento diretto cust.name = … funziona e salta i controlli del metodo (qui il maiuscolo); con private è vietato.

    I metodi get e set

    Gli attributi privati si leggono e si scrivono con metodi pubblici get/set, che possono validare i valori:

    public class PrivateShirt1 {
    private char colorCode = 'U';
    public char getColorCode() { return colorCode; }
    public void setColorCode(char newCode) {
        switch (newCode) {
            case 'R': case 'G': case 'B': case 'U':
                colorCode = newCode; break;
            default:
                System.out.println("Invalid Color Code");
        }
    }
}

    Domande lampo

    Che differenza c’è tra specifica e implementazione?

    La specifica dice cosa offre la classe e come si usa; l’implementazione come lo fa. Sono separate.

    Perché usare un setter invece di un attributo public?

    Perché il setter può controllare il valore (es. solo codici colore validi).

    Ruolo cliente o servente: chi usa le risorse di altre classi?

    Il cliente.

    Il modificatore static

    Attributi e metodi di classe, cosa può fare un metodo statico, classi interne statiche.

    Di solito un attributo esiste solo quando si crea un oggetto con new. Due situazioni in cui non basta:

    • si vuole un’area di memoria comune a tutti gli oggetti della classe;
    • si vuole chiamare un metodo o leggere un attributo senza un oggetto.
    DefinizioneUn membro static appartiene alla classe, non a un oggetto in particolare. Esiste in una sola copia condivisa da tutti gli oggetti, e si può usare sia tramite la classe (Alpha.y) sia tramite un oggetto (a.y).
    public class Alpha {
    int x = 0;           // uno per ogni oggetto
    static int y = 0;    // uno per tutta la classe
    public void beta() { /* modifica x */ }
    public static void gamma() { /* modifica y */ }
}
Alpha.y = 7;
Alpha.gamma();
Alpha a = new Alpha();
a.x = 5;
a.beta();

    Con Alpha A = new Alpha(); Alpha B = new Alpha(); ciascun oggetto ha la sua x, ma y è una sola e gamma() lavora su quella.

    Regola d’esameUn metodo static non può accedere a membri non static (senza un oggetto): quei membri non esistono finché non si crea un oggetto. Un metodo non static invece può usare tutto.

    Esempio

    class StaticTest {
    static int i = 47;
    int j = 0;
    static void incr() { i++; }
}
public class Test {
    public static void main(String args[]) {
        System.out.println(StaticTest.i);   // 47
        StaticTest st1 = new StaticTest();
        StaticTest st2 = new StaticTest();
        st1.j++; st2.j++;                   // ogni oggetto ha la sua j: valgono 1 e 1
        st1.i++; st2.i++;                   // la stessa i: 49
        System.out.println(st1.i);          // 49
        System.out.println(st2.i);          // 49
    }
}

    st1.i++ equivale a StaticTest.i++, a StaticTest.incr() e a st1.incr().

    Quali operazioni sono consentite?

    Dentro il main (statico)Esito
    StaticTest.j❌ non consentita: j non è statica, serve un oggetto
    StaticTest.incr(), StaticTest.i✅ consentite
    st.i, st.j, st.incr() con st = new StaticTest()✅ consentite
    j scritto direttamente nel main della stessa classe❌ non consentita
    i, i++, incr() nella stessa classe✅ consentite, senza il punto: siamo dentro la classe

    Classi interne statiche

    • Un’istanza di una classe interna normale tiene un riferimento implicito all’oggetto esterno che l’ha creata; una classe interna static no.
    • Per creare un oggetto della classe interna statica non serve un oggetto della classe esterna.
    • Da un oggetto della classe interna statica non si accede a un oggetto della classe esterna.
    • Può contenere attributi statici.
    • Una classe interna statica può far parte di un’interfaccia.
    Le slide dicono che le classi interne non possono dichiarare metodi statici: era vero fino a Java 15; da Java 16 è permesso.

    Domande lampo

    Quante copie esistono di un attributo static?

    Una sola, condivisa da tutti gli oggetti.

    Un metodo static può usare this?

    No: non è legato ad alcun oggetto.

    st1.i++ e st2.i++ partendo da 47: quanto vale i?

    49, perché è la stessa variabile.

    Serve un oggetto esterno per creare una classe interna static?

    No.

    Overloading

    Lo stesso nome con più significati, su cosa si distingue, polimorfismo statico.

    I nomi sono importanti: un oggetto dà un nome a una zona di memoria, un metodo a un’azione. Un nome è overloaded quando assume più significati: “lavare la maglia, il cane, la macchina”: è l’oggetto a dare il significato al verbo.

    DefinizioneL’overloading è la definizione di più metodi con lo stesso nome ma parametri diversi nel tipo, nel numero o nell’ordine.
    TrabocchettoNon si può fare overloading sul solo tipo di ritorno: int f() e float f() non possono convivere, perché in una chiamata come f(); il compilatore non saprebbe quale scegliere.
    class Tree {
    int height = 0;
    void info() { System.out.println("Tree is " + height + " feet tall"); }
    void info(String s) { System.out.println(s + ": Tree is " + height + " feet tall"); }
}

public class OverloadingOrder {
    static void print(String s, int i) { System.out.println("String: " + s + ", int: " + i); }
    static void print(int i, String s) { System.out.println("int: " + i + ", String: " + s); }
    public static void main(String[] args) {
        print("String first", 11);
        print(99, "Int first");
    }
}

    Il secondo esempio distingue i metodi solo per l’ordine dei parametri.

    Overloading e polimorfismo

    L’overloading è un esempio di polimorfismo statico: il metodo da chiamare si sceglie in fase di compilazione (associazione statica, early binding).

    Domande lampo

    Su cosa si distinguono due metodi in overload?

    Sul tipo, sul numero o sull’ordine dei parametri.

    Posso distinguerli solo per il tipo di ritorno?

    No.

    L’overloading è polimorfismo statico o dinamico?

    Statico: risolto a compile-time.

    09

    Costruttori e garbage collector

    Costruttore, overload del costruttore, garbage collection generazionale, finalize, persistenza e visibilità.

    Il costruttore

    Molti errori nascono da variabili non inizializzate. Il costruttore permette di non separare creazione e inizializzazione dell’oggetto.

    • Ha lo stesso nome della classe.
    • Non restituisce niente, neanche void.
    • Può avere o no parametri.
    • Viene chiamato da new, che restituisce il riferimento all’oggetto: Albero a = new Albero();
    • Se non se ne definisce nessuno, Java crea quello di default (senza parametri), che alloca semplicemente l’oggetto.
    public class Albero {
    int altezza = 0;
    public Albero() {
        System.out.println("Costruito un albero di altezza " + altezza);
    }
    public Albero(int h) {     // overload del costruttore
        altezza = h;
        System.out.println("Costruito un albero di altezza " + altezza);
    }
}
    TrabocchettoIl costruttore di default esiste solo se non ne scrivi nessuno. Se definisci solo Albero(int h), new Albero() non compila più.

    Esempio di overload: new Shirt(), new Shirt('G'), new Shirt('B', 1000) chiamano tre costruttori diversi.

    Il “distruttore” e il garbage collector

    Gli oggetti sono creati dinamicamente e, finito il loro uso, la memoria va liberata. In Java se ne occupa il garbage collector:

    • un oggetto può essere deallocato quando nessun riferimento punta più a lui;
    • non si sa a priori quando interverrà il garbage collector.

    Il GC è un thread daemon in background che libera l’heap dagli oggetti non più raggiungibili. Nelle slide è descritto con il reference counting: ogni oggetto ha un contatore dei riferimenti; quando arriva a zero l’oggetto è candidato alla deallocazione.

    String s1 = new String("casa1");
String s2 = new String("casa2");
s1 = s2;     // "casa1" non ha più riferimenti
s1 = null;   // s2 punta ancora a "casa2"
s2 = null;   // ora anche "casa2" può essere distrutto
    Le JVM moderne in pratica non contano i riferimenti: partono dalle radici (stack, variabili statiche) e marcano ciò che è raggiungibile. Così vengono raccolti anche gli oggetti che si puntano a vicenda. All’esame usa la descrizione delle slide.

    Le fasi della garbage collection

    1. Marking→2. Cancellazione normale→2b. Compattazione
    1. Marking: si identificano i pezzi di heap in uso e quelli no, scansionando tutti gli oggetti (può richiedere molto tempo).
    2. Cancellazione normale: si rimuovono gli oggetti senza riferimenti; l’allocatore tiene i riferimenti ai blocchi liberi.
    3. Compattazione: si avvicinano gli oggetti rimasti, così le nuove allocazioni sono più semplici e veloci.

    Scorrere tutti gli oggetti dà una latenza crescente. Ma la maggior parte degli oggetti ha vita breve: da qui la garbage collection generazionale.

    GC generazionale

    GenerazioneCosa contieneRaccolta
    Giovane (eden + due spazi survivor S0, S1)Tutti i nuovi oggettiMinor GC quando l’eden si riempie: veloce (alta mortalità, poca memoria)
    VecchiaGli oggetti sopravvissuti oltre una soglia di età (es. 8)Major GC: più lenta, attivata più di rado
    Permanente (fino a Java 7)Metadati di classi e metodi usati dalla JVMRimossa in Java 8
    1. I nuovi oggetti vanno nell’eden; i due spazi survivor sono vuoti.
    2. Quando l’eden si riempie parte una minor GC: gli oggetti referenziati vanno in S0, gli altri vengono eliminati con l’eden.
    3. Alla minor GC successiva gli oggetti vivi di eden e S0 passano in S1 con età incrementata; eden e S0 vengono svuotati.
    4. Alla successiva si ripete invertendo i survivor (si torna in S0).
    5. Superata la soglia di età, gli oggetti sono promossi alla vecchia generazione; prima o poi una major GC la ripulisce e la compatta.

    Sia la minor sia la major GC sono eventi “Stop the World”: tutti i thread dell’applicazione si fermano fino alla fine.

    CMS · Concurrent Mark Sweep

    Minimizza le pause lavorando insieme ai thread dell’applicazione. Di norma non compatta: rischio di frammentazione, compensato con un heap più grande. Per applicazioni che chiedono pause brevi.

    G1 · Garbage-First

    Per heap oltre 4 GB: divide l’heap in regioni da 1 a 32 MB; dopo una marcatura globale raccoglie prima le regioni più vuote (da qui il nome). Usa un modello di previsione.

    finalize

    Java non distrugge l’oggetto quando finisce il suo ambito di visibilità, ma più tardi, in un momento non prevedibile. Per fare operazioni prima della distruzione si può definire finalize(), chiamato appena prima della deallocazione.

    public class Oggetto {
    static int n_obj = 0;           // conta le istanze vive
    public Oggetto() { n_obj++; }
    public void finalize() { n_obj--; }
}

    Problemi dei finalizzatori:

    • non si sa quando verranno eseguiti: le risorse potrebbero finire prima;
    • portabilità: l’algoritmo di GC dipende dalla JVM;
    • prestazioni: distruggere un oggetto con finalize non vuoto costa di più;
    • niente gestione delle eccezioni: se finalize lancia un’eccezione la finalizzazione si interrompe e l’oggetto resta in uno stato improprio.
    finalize è deprecato da Java 9. System.gc() chiede di far partire la raccolta, ma non la garantisce.

    Persistenza e visibilità

    Variabile di un metodo

    Vale finché il metodo non termina.

    Attributo di un oggetto

    Vale finché l’oggetto è vivo, cioè finché qualche riferimento punta a lui.

    Vantaggi del GC

    Più produttività; integrità: non si può far andare in crash la JVM liberando male la memoria.

    Svantaggi

    Un overhead considerevole che può pesare sulle prestazioni.

    La keyword this

    Il riferimento all’oggetto corrente, distinguere attributi e parametri, restituire this, chiamare un costruttore da un altro.

    Dentro una classe si richiamano metodi e attributi senza indicare un oggetto. Ma se a.incr() e b.incr() eseguono lo stesso codice, come fa incr a sapere su quale i lavorare?

    DefinizioneIl compilatore passa segretamente al metodo il riferimento all’oggetto corrente, accessibile con la parola this. this si usa solo dentro un metodo (non statico), come un qualunque riferimento. Chiamare pick() o this.pick() è la stessa cosa.

    Distinguere attributo e parametro

    public class Contatore {
    int i = 0;
    public void incr(int i) { this.i = i; }   // this.i è l'attributo, i il parametro
}

    Restituire l’oggetto stesso

    public class Contatore {
    int cont = 0;
    public Contatore incr() {
        cont++;
        return this;
    }
}
c.incr().incr().incr();   // chiamate in catena

    Chiamare un costruttore da un altro

    public class Flower {
    int petalCount = 0;
    String s = "null";
    Flower(int petals) { petalCount = petals; }
    Flower(String ss) { s = ss; }
    Flower(String s, int petals) {
        this(petals);
        //! this(s);      // non se ne possono chiamare due
        this.s = s;       // altro uso di this
    }
    Flower() { this("hi", 47); }
}
    Regolethis(...) chiama un altro costruttore della stessa classe: si può usare solo dentro un costruttore, deve essere la prima istruzione e se ne può chiamare uno solo.

    Che cosa contiene this?

    Il riferimento all’oggetto su cui è stato chiamato il metodo.

    Si può usare this in un metodo static?

    No.

    Come prima istruzione, e una volta sola.

    A cosa servono, come si dichiarano, import, relazione con le cartelle e il CLASSPATH.

    I package servono a:

    • organizzare il codice;
    • sviluppare e riusare librerie.

    Information hiding

    Accesso package, public, private, come garantire l’accesso, costruttori privati, metodi di utilità.
    DefinizioneL’information hiding è il meccanismo che permette di nascondere l’implementazione di una classe, regolando l’accesso ai suoi membri da parte di oggetti di altre classi. Gli specificatori (public, private…) vanno messi su ogni attributo e ogni metodo.

    Accesso package (“friendly”)

    Se non si specifica niente:

    • tutte le classi del package corrente possono accedere al membro;
    • le classi fuori dal package no.

    Un file appartiene a un solo package, quindi le classi dello stesso file si vedono a vicenda i membri senza specificatore.

    Come garantire l’accesso a un membro

    1. Renderlo public: tutti, ovunque, possono usarlo.
    2. Non mettere specificatore e tenere le classi nello stesso package.
    3. Scrivere metodi get/set per gli attributi privati: è la scelta consigliata.

    public

    package c05.dessert;
public class Cookie {
    public Cookie() { System.out.println("Cookie constructor"); }
    void bite() { System.out.println("bite"); }   // accesso package
}

import c05.dessert.*;
public class Dinner {
    public static void main(String[] args) {
        Cookie x = new Cookie();
        //! x.bite();   // non accessibile: Dinner è in un altro package
    }
}

    Cookie.class deve stare in c05/dessert sotto una cartella del CLASSPATH. Se nel CLASSPATH manca ., Java non cerca nella cartella corrente.

    private

    Solo la classe stessa può accedere ai suoi membri privati: nemmeno le classi dello stesso package. Così si possono cambiare quei membri senza che le altre classi se ne accorgano, utile quando più persone lavorano allo stesso package.

    class Sundae {
    private Sundae() {}
    static Sundae makeASundae() { return new Sundae(); }
}
public class IceCream {
    public static void main(String[] args) {
        //! Sundae x = new Sundae();      // costruttore privato
        Sundae x = Sundae.makeASundae();   // creazione controllata
    }
}

    Un costruttore privato permette di controllare come si creano gli oggetti. Anche i metodi di utilità interni conviene renderli private: chi ha scritto la classe può cambiarli o toglierli quando vuole.

    Da non confondereAccesso package e private: con il primo le classi dello stesso package vedono il membro, con il secondo no.

    Domande lampo

    Senza specificatore, chi vede il membro?

    Le classi dello stesso package.

    Una classe dello stesso package vede un membro private?

    No.

    Perché rendere private un costruttore?

    Per controllare come vengono creati gli oggetti (es. con un metodo statico).

    Qual è il modo consigliato per dare accesso a un attributo privato?

    I metodi get e set.

    Ereditarietà

    Composizione ed ereditarietà, extends, overriding, super, protected, costruttori, ereditarietà multipla in C++.

    Due modi di riusare il codice

    Composizione

    Gli attributi della nuova classe sono oggetti di classi già esistenti. Relazione “ha un”. Si usa quando la classe deve fornire le funzionalità di classi esistenti.

    Ereditarietà

    La nuova classe estende una classe esistente. Relazione “è un”. Si usa quando la classe deve presentare un’estensione dell’interfaccia della vecchia classe.

    public class Car {
    public Engine engine = new Engine();
    public Wheel[] wheel = new Wheel[4];   // 4 riferimenti null, non 4 ruote!
    public Door left, right;
    public Car() {
        left = new Door(); right = new Door();
        for (int i = 0; i < 4; i++) wheel[i] = new Wheel();
    }
    public static void main(String[] args) {
        Car car = new Car();
        car.left.window.rollup();
        car.wheel[0].inflate(72);
    }
}

    Gli oggetti componenti si inizializzano: nella dichiarazione, nel costruttore oppure appena prima di usarli.

    Che cos’è l’ereditarietà

    DefinizioneL’ereditarietà descrive una nuova classe nei termini di una già esistente. Se B eredita da A, B ha sicuramente tutti gli attributi e i metodi di A e può estenderla. Equivale all’inclusione tra insiemi: ogni B è anche un A. A è la classe base (superclasse, ereditata), B la classe derivata (sottoclasse, ereditante).

    Esempio: Veicolo (pilota, ruote) → Auto (volante, motore, targa) e Bici (manubrio, pedali); Autotreno eredita da Auto (rimorchio).

    Generalizzazione

    Dal particolare al generale: risalendo la gerarchia.

    Specializzazione

    Dal generale al particolare: scendendo la gerarchia.

    Una slide scrive “specializzazione: dal particolare al generale”: è un refuso, la specializzazione va dal generale al particolare.

    Vantaggi: si riducono i tempi di sviluppo, perché si scrive meno codice quando si definisce un sottotipo o si adatta una classe esistente. Non serve conoscere in dettaglio il codice riusato: si modifica solo la parte di interesse.

    Cosa può fare la classe derivata

    Una sottoclasse si ottiene per aggiunta, occultamento o ridefinizione di membri. Può:

    • usare i metodi della classe base;
    • modificare i metodi della classe base (overriding);
    • definire nuovi metodi propri.

    Se base ha f() e f1() e derivata ridefinisce f1() e aggiunge g(): b.f(), d.f(), b.f1(), d.f1(), d.g() sono validi, b.g() no. L’oggetto derivato contiene un sotto-oggetto della classe base più la sua parte propria.

    MeccanismoCosa fa
    extends (Java), : (C++)Indica la classe da ereditare. Java permette di ereditare una sola classe; il C++ ha l’ereditarietà multipla.
    OverridingSi ridefinisce un metodo della classe base con la stessa firma, specializzandone o sostituendone il comportamento.
    OverloadingIn Java un overload, nella classe derivata, di un metodo della classe base non lo oscura: restano disponibili entrambi.
    ShadowingOscurare un metodo o un attributo della classe madre.

    In Java la derivazione è sempre pubblica: non si può scegliere la modalità (public, protected, private) come in C++.

    Come si cerca un metodo

    L’interprete cerca il metodo prima nella classe dell’oggetto; se non c’è, nella superclasse, e così via risalendo la gerarchia. Viene eseguito il primo trovato con la stessa firma (nome e parametri).

    class BaseNonno { public void stampa() { System.out.println("stampa()"); } }
class BasePadre extends BaseNonno { public void stampa(int i) { System.out.println("stampa(int)"); } }
public class Derivata extends BasePadre {
    public void stampa(float f) { System.out.println("stampa(float)"); }
    public static void main(String args[]) {
        Derivata f = new Derivata();
        f.stampa(5);      // stampa(int)
        f.stampa();       // stampa()
        f.stampa(3.5f);   // stampa(float)
    }
}
    Nella slide c’è f.stampa(3.5): 3.5 è un double e non esiste stampa(double), quindi non compila. Con 3.5f funziona. L’esempio mostra che i tre overload convivono.

    Esempio: Struccante e Detergente

    class Struccante {
    private String s = "Detersivo";
    public String toString() { return s; }
    public void append(String a) { s += a; }
    public void dilute() { append(" dilute()"); }
    public void apply() { append(" apply()"); }
    public void pulisci() { append(" pulisci()"); }
}

    Ereditarietà e costruttori

    L’oggetto derivato contiene un sotto-oggetto della classe base, che va inizializzato chiamando il suo costruttore con super(...):

    • implicita, se la classe base ha un costruttore senza argomenti: il compilatore mette super() in testa al costruttore derivato;
    • esplicita, se il costruttore della base vuole almeno un argomento.
    class Art { Art() { System.out.println("Art constructor"); } }
class Drawing extends Art { Drawing() { System.out.println("Drawing constructor"); } }
public class Cartoon extends Drawing {
    public Cartoon() { System.out.println("Cartoon constructor"); }
    public static void main(String[] args) { new Cartoon(); }
}
// Output: Art constructor / Drawing constructor / Cartoon constructor

class Game { Game(int i) { System.out.println("Game constructor " + i); } }
class BoardGame extends Game {

public class Chess extends BoardGame {

    Ordine di costruzione

    1. si chiama ricorsivamente il costruttore della classe base, partendo dalla radice della gerarchia;
    2. si inizializzano gli attributi nell’ordine di dichiarazione;
    3. si esegue il corpo del costruttore.

    La distruzione avviene al contrario: prima la parte della classe derivata.

    class Meal { Meal() { System.out.println("Meal()"); } }
class Lunch extends Meal { Lunch() { System.out.println("Lunch()"); } }
class PortableLunch extends Lunch { PortableLunch() { System.out.println("PortableLunch()"); } }
public class Sandwich extends PortableLunch {
    private Bread b = new Bread();
    private Cheese c = new Cheese();
    private Lettuce l = new Lettuce();
    public Sandwich() { System.out.println("Sandwich()"); }
}
// Output: Meal() Lunch() PortableLunch() Bread() Cheese() Lettuce() Sandwich()

    Sviluppo incrementale

    Ogni nuova classe completa quella ereditata senza modificarne il codice: se la base funzionava, un errore può stare solo nel codice nuovo, e non compromette la classe base.

    Cosa accade in C++: ereditarietà multipla

    Se C deriva da B1 e B2, che derivano entrambe da A (il “diamante”), A viene replicata:

    • memoria doppia per i membri di A;
    • ambiguità: accedendo a un membro di A il compilatore non sa se passare da B1 o da B2. Si risolve qualificando: ogg.B1::ma, ogg.B2::ma.

    Entrambi i problemi si risolvono dichiarando A classe base virtuale: class B1 : virtual protected A, class B2 : virtual public A. Così in C c’è una sola copia di A, e il costruttore di C deve chiamare anche quello di A (la “nipote” si occupa della “nonna”).

    Modalità di derivazione in C++

    In C++ i membri possono essere privati, protetti o pubblici, e in più si sceglie come si trasmettono i diritti di accesso (P base, F figlia, N nipote, U utente):

    F deriva da P in modalitàEffetto
    pubblicaLa parte pubblica di P è accessibile a N e U, quella protetta solo a N.
    protettaParte pubblica e protetta accessibili a N, ma non a U.
    privata (default in C++)I diritti non vengono trasmessi.

    Upcasting

    Un oggetto derivato è anche un oggetto base, la classe Object e i suoi metodi.
    DefinizioneLa cosa più importante dell’ereditarietà non è aggiungere funzionalità, ma che un oggetto della classe derivata è anche un oggetto della classe base. Il linguaggio lo supporta: Padre p = new Figlio();. Convertire un riferimento derivato in uno base si chiama upcasting ed è sempre sicuro e implicito.
    class Instrument {
    public void play() { System.out.println("Play Instrument"); }
    static void tune(Instrument i) { i.play(); }
}
public class Wind extends Instrument {
    public void play() { System.out.println("Play Wind"); }
    public static void main(String[] args) {
        Instrument flute2 = new Wind();   // upcasting
        flute2.play();                    // "Play Wind"
        Instrument.tune(flute2);          // "Play Wind"
        Instrument.tune(new Wind());      // upcasting nel passaggio del parametro: "Play Wind"
        Instrument.tune(new Instrument());// "Play Instrument"
    }
}

    Un messaggio che si può inviare alla classe base si può inviare anche alla derivata: Wind eredita l’interfaccia di Instrument. Con flute2.play() viene eseguito il play di Wind, perché l’oggetto è un Wind (vedi polimorfismo, cap. 17).

    • Object non ha superclasse: è la radice.

    Polimorfismo e classi astratte

    Binding statico e dinamico, estensibilità, toString, clone, @Override, classi astratte, metodi polimorfi nel costruttore.

    Il polimorfismo è il terzo meccanismo fondamentale della programmazione a oggetti, dopo data abstraction / information hiding ed ereditarietà (riuso). Permette di estendere un progetto aggiungendo funzionalità.

    DefinizioneIl polimorfismo è la capacità di oggetti di classi derivate da una base comune di rispondere in modo diverso allo stesso messaggio. Un’entità è polimorfa se può riferirsi, nel tempo, a classi diverse.

    Polimorfismo statico

    A tempo di compilazione: early binding, binding statico. Esempio: l’overloading.

    Polimorfismo dinamico

    A tempo di esecuzione: late binding, binding dinamico. Esempio: l’overriding chiamato tramite un riferimento alla base.

    Il binding è il collegamento tra la chiamata di un metodo e il codice che la esegue.

    Perché serve: le figure

    Una gerarchia Figura con Triangolo, Rettangolo, Quadrato, tutte con disegna(), e un array Figura A[N] di figure miste.

    Senza polimorfismo

    for i = 1 to N
  switch (A[i].tipo)
    case Triangolo: A[i].DisegnaTriangolo()
    case Rettangolo: A[i].DisegnaRettangolo()
    case Quadrato: A[i].DisegnaQuadrato()

    Per ogni nuova figura va cambiato lo switch.

    Con polimorfismo

    for i = 1 to N
  A[i].disegna()

    A run-time si sceglie il disegna() giusto. Aggiungendo Cerchio il ciclo non cambia.

    Il polimorfismo dà estensibilità: minimizza il codice da modificare quando si aggiungono classi e funzionalità.

    class Shape { void draw() {} void erase() {} }
class Circle extends Shape { void draw() { System.out.println("Circle.draw()"); } }
class Square extends Shape { void draw() { System.out.println("Square.draw()"); } }
class Triangle extends Shape { void draw() { System.out.println("Triangle.draw()"); } }

Shape[] s = new Shape[9];
for (int i = 0; i < s.length; i++) s[i] = gen.next();   // classi note solo a run-time
for (int i = 0; i < s.length; i++) s[i].draw();         // chiamata polimorfa

    Strumenti musicali

    class Instrument { public void play(Note n) { System.out.println("Instrument.play() " + n); } }
class Wind extends Instrument { public void play(Note n) { System.out.println("Wind.play() " + n); } }
class Stringed extends Instrument { public void play(Note n) { System.out.println("Stringed.play() " + n); } }
class Brass extends Instrument { public void play(Note n) { System.out.println("Brass.play() " + n); } }

public class Music {

    public static void main(String[] args) {
        tune(new Wind());       // upcasting
        tune(new Stringed());
        tune(new Brass());

}
    Nella slide Instrument ha play() senza parametri e le sottoclassi play(Note n): sarebbe un overload, non un override, e i.play(Note.MIDDLE_C) non compilerebbe. Perché funzioni il polimorfismo la firma deve essere la stessa.

    L’alternativa senza upcasting è scrivere un tune per ogni strumento (tune(Wind), tune(Stringed), tune(Brass)): codice ripetuto da aggiornare per ogni nuovo strumento.

    Il polimorfismo separa il “cosa” dal “come”: si esegue il codice specifico della classe derivata senza conoscerne il tipo.

    Il metodo clone

    protected Object clone() throws CloneNotSupportedException crea un oggetto indipendente dall’originale. Restituisce un Object (serve un cast) ed è protected: va ridefinito public.

    class Studente implements Cloneable {   // interfaccia "marcatore"
    String nome; int anno;
    public Object clone() {
        try { return super.clone(); }
        catch (CloneNotSupportedException e) { System.exit(1); }
        return null;   // qui non arriva mai
    }
}
Studente q = (Studente) p.clone();   // cast obbligatorio

    Copia superficiale (shallow)

    È quella di super.clone(): si copiano i valori degli attributi; per gli attributi oggetto si copia solo il riferimento, quindi le modifiche all’oggetto interno si vedono in entrambi. Più veloce.

    Copia profonda (deep)

    Si duplicano anche gli oggetti interni (es. un nuovo array). Più lenta e costosa, ma più sicura.

    class V implements Cloneable {
    int x[];
    public Object clone() {
        try {
            V tmp = (V) super.clone();
            tmp.x = x.clone();         // copia profonda dell'array
            return tmp;
        } catch (CloneNotSupportedException e) { return null; }
    }
}
V p1 = new V(5); V p2 = (V) p1.clone();
p1.x[0] = 9;   // con la copia superficiale lo vedrebbe anche p2; con quella profonda no

    La scelta dipende dai campi: int e String (immutabile) vanno bene in copia superficiale; un campo mutabile come Date hireDate va copiato in profondità (e.hireDate = (Date) hireDate.clone();); per boss dipende dal contesto, di solito superficiale. Non tutti gli oggetti sono clonabili: String non lo è.

    Esercizio tipicoCon P p2 = p1; e P p3 = (P) p1.clone();, dopo p1.x = 7: p2.x vale 7 (stesso oggetto), p3.x resta 5 (oggetto clonato).

    Controllo dell’override: @Override

    public class Animale {
    private String nome;
    @Override
    public boolean equals(Animale a) { ... }   // errore: non fa override di niente!
}
public class Animale {
    private String nome;
    @Override
    public boolean equals(Object a) { return nome.equals(((Animale) a).nome); }   // corretto
}

    Senza annotazione equals(Animale) sarebbe un overload silenzioso. Con @Override il compilatore controlla che il metodo ridefinisca davvero un metodo della superclasse.

    Classi astratte

    Problemi che si vogliono evitare a compile-time: sbagliare il prototipo e creare un metodo nuovo invece di ridefinirlo; dimenticare l’overriding; chiamare un metodo base solo fittizio; istanziare per errore una classe base fittizia.

    DefinizioneUna classe è astratta (abstract) quando uno o più metodi non sono implementati: definisce l’interfaccia delle classi derivate ed eventualmente un’implementazione parziale. Non si può istanziare.
    abstract class Instrument {
    private int i;
    public String what() { return "Instrument"; }
    public abstract void play(Note n);
    public abstract void adjust();
}
    • La presenza di un metodo astratto obbliga a dichiarare la classe abstract.
    • what() è implementato e può non essere ridefinito.
    • Una sottoclasse concreta che non ridefinisce i metodi astratti dà errore di compilazione (o deve essere a sua volta astratta).
    • Si può dichiarare abstract anche una classe senza metodi astratti, per impedire che venga istanziata.
    • Un metodo astratto è per definizione polimorfo.

    Metodi polimorfi nel costruttore: pericolo

    abstract class Glyph {
    abstract void draw();
    Glyph() {
        System.out.println("Glyph() before draw()");

        System.out.println("Glyph() after draw()");

}
class RoundGlyph extends Glyph {

    RoundGlyph(int r) { radius = r; System.out.println("RoundGlyph.RoundGlyph(), radius = " + radius); }

    1. La memoria dell’oggetto è azzerata prima di tutto.
    2. Si chiamano i costruttori delle superclassi: draw() ridefinito viene eseguito prima del costruttore di RoundGlyph, e vede radius = 0.
    3. Si inizializzano gli attributi nell’ordine di dichiarazione.
    4. Si esegue il corpo del costruttore derivato.

    Il costrutto final

    final su tipi semplici, riferimenti, parametri, metodi e classi; blank final; private e final; funzioni inline.

    final ha significati diversi a seconda di dove si usa: tipi semplici, riferimenti, metodi, classi.

    final su tipi semplici

    • Una costante a tempo di compilazione: il valore può essere sostituito direttamente nel bytecode.
    • Oppure un valore calcolato a run-time che, una volta inizializzato, non cambia più.
    • static final: una sola locazione comune a tutti gli oggetti, che non può cambiare.

    final sui riferimenti

    Un riferimento final si inizializza una volta e poi non può puntare a un altro oggetto. Ma l’oggetto puntato può cambiare: renderlo immutabile dipende da come è scritta la sua classe.

    public class FinalData {
    private final int VAL_ONE = 9;                  // costante di compilazione
    public static final int VAL_THREE = 39;
    static final int i5 = rand.nextInt(20);          // costante di run-time
    private static final Value v = new Value(33);
    private final int[] a = {1, 2, 3, 4, 5, 6};

    void prova() {
        v.i++;                  // OK: cambia l'oggetto, non il riferimento
        //! v = new Value(5);   // errore: v è final
        a[0]++;                 // OK: l'array non è costante
        //! a = new int[3];     // errore
    }
}

    Blank final

    Variabili final non inizializzate nella dichiarazione: devono essere inizializzate in ogni costruttore, altrimenti errore di compilazione. Così ogni oggetto può avere un valore diverso ma immutabile.

    public class BlankFinal {
    private final int j;
    private final Poppet p;
    public BlankFinal(int x) {
        j = x;
        p = new Poppet(x);
    }
}

    Parametri final

    void with(final Gizmo g) {
    //! g = new Gizmo();   // errore: g è final
}

    Metodi final

    • Un metodo final non può essere ridefinito (overriding) nelle classi derivate.
    • Può diventare inline: il compilatore copia il corpo al posto della chiamata (più efficienza).
    • Un metodo private è implicitamente final: non essendo visibile non può essere ereditato. private è “più forte” di final.
    Funzioni inline in C/C++: il codice della funzione viene inserito nel punto della chiamata invece del salto a sottoprogramma. Va usato solo per funzioni brevissime, altrimenti il guadagno è irrilevante e il codice cresce. In Java non si può chiedere l’inlining: le ottimizzazioni le fa la JVM a run-time.

    “Override” di un metodo privato

    class WithFinals {
    private final void f() { System.out.println("WithFinals.f()"); }
    public void g() { System.out.println("WithFinals.g()"); }
}
class OverridingPrivate extends WithFinals {
    public final void f() { System.out.println("OverridingPrivate.f()"); }
    public void g() { System.out.println("OverridingPrivate.g()"); }
}
OverridingPrivate op = new OverridingPrivate();
op.f(); op.g();             // OverridingPrivate.f(), OverridingPrivate.g()
WithFinals wf = op;         // upcast
//! wf.f();                 // errore: f() è private in WithFinals
wf.g();                     // OverridingPrivate.g() (override vero)

    Il compilatore non dà errore su f() della derivata, ma non è un override: è un nuovo metodo che ha per caso lo stesso nome, perché quello privato della base non è visibile.

    Downcasting

    Ereditarietà pura ed estensione, cosa si perde con l’upcasting, recuperarlo con un cast esplicito.

    Ereditarietà pura (“is-a”)

    Le sottoclassi (Circle, Square, Triangle) ridefiniscono solo i metodi della base (draw, erase): chi parla con Shape può usare qualunque figura, anche nuova.

    Estensione (“is-like-a”)

    MoreUseful estende Useful (f, g) aggiungendo metodi (u, v, w).

    Contro dell’upcasting: chi vede l’oggetto come Useful vede solo la parte Useful; la parte MoreUseful è inaccessibile.

    DefinizioneIl downcasting converte un riferimento della classe base in uno della classe derivata, per recuperare le caratteristiche perse con l’upcasting. Va forzato con un cast esplicito perché non è sempre lecito: tocca al programmatore sapere cosa sta facendo. Se il tipo è sbagliato si ha un’eccezione a run-time (ClassCastException).
    class Useful { public void f() {} public void g() {} }
class MoreUseful extends Useful {
    public void f() {} public void g() {}
    public void u() {} public void v() {} public void w() {}
}
public class RTTI {
    public static void main(String[] args) {
        Useful[] x = { new Useful(), new MoreUseful() };
        x[0].f(); x[0].g();
        x[1].f(); x[1].g();
        //! x[1].u();                     // compile time: u() non esiste in Useful
        MoreUseful mu = (MoreUseful) x[1];
        mu.u();
        ((MoreUseful) x[1]).u();          // downcast / RTTI: OK
        ((MoreUseful) x[0]).u();          // ClassCastException a run-time
    }
}

    Il controllo a run-time del tipo si chiama RTTI (Run-Time Type Identification). Per evitare l’eccezione si può controllare prima con instanceof: if (x[0] instanceof MoreUseful) …

    Da non confondereUpcasting: implicito e sempre sicuro. Downcasting: esplicito, controllato a run-time, può lanciare ClassCastException. L’errore “metodo non trovato” su x[1].u() è invece di compilazione.

    Domande lampo

    Perché il downcast va scritto esplicitamente?

    Perché non è sempre lecito: l’oggetto potrebbe non essere della sottoclasse.

    ((MoreUseful) x[0]).u() con x[0] = new Useful()?

    Compila, ma a run-time lancia ClassCastException.

    “is-a” o “is-like-a” per una sottoclasse che aggiunge metodi?

    is-like-a (estensione).

    Interfacce

    Classi completamente astratte, implements, ereditarietà multipla, collisioni di nomi, costanti, metodi default e static.
    DefinizioneUn’interfaccia definisce una classe completamente astratta: dichiara metodi senza implementazione. I metodi sono automaticamente public (e abstract); gli attributi sono solo costanti: static, final e inizializzate (niente blank final).
    interface Instrument {
    int i = 5;              // static e final
    void play(Note n);      // automaticamente public
    String what();
    void adjust();
}
class Wind implements Instrument {
    public void play(Note n) { System.out.println("Wind.play() " + n); }
    public String what() { return "Wind"; }
    public void adjust() { }
}
class Woodwind extends Wind {
    public void play(Note n) { System.out.println("Woodwind.play() " + n); }
    public String what() { return "Woodwind"; }
}
    TrabocchettoLa classe che implementa deve dichiarare i metodi public: se li lascia senza specificatore sono “friendly”, cioè meno visibili di quelli dell’interfaccia, e il compilatore dà errore.

    Ereditarietà multipla

    Il C++ permette di ereditare più classi, ma ciò causa collisioni. Java permette di estendere una sola classe e implementare più interfacce (implements), così un oggetto può subire l’upcasting verso più tipi.

    interface CanFight { void fight(); }
interface CanSwim { void swim(); }
interface CanFly { void fly(); }
class ActionCharacter { public void actionFight() { } }
class Hero extends ActionCharacter implements CanFight, CanSwim, CanFly {
    public void fight() { } public void swim() { } public void fly() { }
}
public class Adventure {
    static void t(CanFight x) { x.fight(); }
    static void u(CanSwim x) { x.swim(); }
    static void v(CanFly x) { x.fly(); }
    static void w(ActionCharacter x) { x.actionFight(); }
    public static void main(String[] args) {
        Hero h = new Hero();
        t(h); u(h); v(h); w(h);   // Hero trattato come quattro tipi diversi
    }
}

    Collisioni di nomi

    interface I1 { void f(); }
interface I2 { int f(int i); }
interface I3 { int f(); }
class C { public int f() { return 1; } }

class C2 implements I1, I2 { public void f() {} public int f(int i) { return 1; } }   // OK: overload
class C3 extends C implements I2 { public int f(int i) { return 1; } }                 // OK: overload
class C4 extends C implements I3 { public int f() { return 1; } }                      // OK: identici
class C5 extends C implements I1 { }      // ERRORE: f() con tipi di ritorno incompatibili (int e void)
interface I4 extends I1, I3 { }           // ERRORE: I1 e I3 incompatibili

    Due metodi con lo stesso nome e parametri ma tipo di ritorno diverso non possono convivere.

class DragonZilla implements DangerousMonster {

}

    Metodi default e static (Java 8)

    Per far evolvere le API senza rompere le classi esistenti, da Java 8 un’interfaccia può avere:

    • metodi default, con un’implementazione predefinita. Una classe può ridefinirli; l’implementazione della classe ha la precedenza.
    • metodi static con implementazione, utili come metodi di utilità: MyInterface.print("Hello");
    public interface ResourceLoader {
    Resource load(String resourcePath);
    default Resource load(Path resourcePath) { /* implementazione di default */ }
}

    Le interfacce sono un modo per ottenere il polimorfismo.

    Classe astratta

    Può avere attributi normali, costruttori, metodi implementati. Si estende (una sola).

    Interfaccia

    Solo costanti; metodi astratti (più default e static da Java 8). Si implementa (anche più di una).

    Di che tipo sono gli attributi di un’interfaccia?

    Costanti: static, final e inizializzati.

    Quante interfacce può implementare una classe?

    Quante vuole; ma estende una sola classe.

    Un’interfaccia può estendere più interfacce?

    Perché f() di C restituisce int e f() di I1 void: tipi di ritorno incompatibili.

    A cosa servono i metodi default?

    A dare un’implementazione predefinita, così le classi esistenti non devono cambiare quando l’interfaccia cresce.

    Programmazione generica

    Il problema (void*, macro), i generics di Java, classi e interfacce generiche, metodi generici, parametri limitati.
    DefinizioneSe un algoritmo o una struttura dati si possono descrivere indipendentemente dal tipo dei dati, si possono scrivere come concetto generale parametrizzato sul tipo. Questa è la programmazione generica.

    Il problema

    • In C (corso di PSD) si usava void* e un’interfaccia in un header (typedef void *Item;): molto lavoro e nessun controllo del compilatore sulla type safety, quindi errori a run-time.
    • Una funzione max per int, char e float richiede tre funzioni con lo stesso corpo.
    • Una macro #define MAX(a,b) (((a)>(b))?(a):(b)) non controlla i tipi e non valuta i parametri: con MAX(++i, ++j) e i = 10, j = 5 il risultato è 12, non 11, perché ++i viene eseguito due volte (nel test e nel ramo scelto).

    I generics di Java

    Da JDK 5.0 classi, interfacce e metodi possono avere parametri di tipo: come i parametri formali dei metodi, ma ricevono tipi invece di valori. Assomigliano ai template del C++.

    • Controllo dei tipi più forte a compile-time: gli errori si scoprono prima, quando è più facile correggerli.
    • Niente cast quando si estrae un elemento.
    • Algoritmi generici, type safe e leggibili.
    List list = new ArrayList();
list.add("hello");
String s = (String) list.get(0);      // cast necessario

List<String> list = new ArrayList<String>();
list.add("hello");
String s = list.get(0);               // niente cast: il compilatore conosce il tipo

    Classi generiche

    public class Box {             // versione con Object: nessun controllo
    private Object object;
    public void set(Object object) { this.object = object; }
    public Object get() { return object; }
}

public class Box<T> {          // versione generica
    private T t;
    public void set(T t) { this.t = t; }
    public T get() { return t; }
}

Box<Integer> integerBox = new Box<Integer>();   // invocazione: tipo parametrizzato

    Con la versione Object qualcuno potrebbe mettere un Integer e qualcun altro aspettarsi una String: errore a run-time. T può essere qualunque tipo non primitivo: classe, interfaccia, array o un’altra variabile di tipo. Box<Integer> integerBox; non crea un oggetto: dichiara un riferimento a un Box di Integer.

    Sintassi con n parametri: class Nome<T1, T2, …, Tn> { }. Per convenzione i nomi sono una lettera maiuscola:

    LetteraSignificato
    EElemento
    KChiave
    NNumero
    TTipo
    VValore
    S, U, V…Secondo, terzo, quarto tipo

    ArrayList<T> e Vector<T>

    • ArrayList ha lo scopo di un array ma cambia dimensione durante l’esecuzione; è meno efficiente di un array. Sta in java.util.
    • Il tipo base T deve essere un tipo strutturato: per i tipi semplici si usano le classi wrapper (Integer, Double…).
    • Indici da 0 a size() - 1, errore fuori range. Metodi: get(i), set(i, v) (sovrascrive), add(v) / add(i, v), remove(i), size().
    • Vector<T> fa le stesse cose con qualche metodo in più, ma è più vecchia e meno efficiente.

    Metodi generici

    Un metodo generico introduce propri parametri di tipo, validi solo nel metodo. La lista va tra parentesi angolari prima del tipo di ritorno. Possono essere statici o no, anche costruttori.

    public class Util {
    public static <K, V> boolean compare(Pair<K, V> p1, Pair<K, V> p2) {
        return p1.getKey().equals(p2.getKey()) && p1.getValue().equals(p2.getValue());
    }
}

    Parametri limitati (bounded)

    Per accettare solo certi tipi si mette un limite superiore con extends (vale sia per le classi sia per le interfacce):

    System.out.println("T: " + t.toString());

    Java I/O

    Stream, file di testo e binari, buffering, stream di byte e di caratteri, incapsulamento, console, Scanner.

    Input: dati che arrivano al programma (da tastiera o file). Output: dati che escono dal programma (a video o su file). I file danno una copia permanente, permettono lo scambio tra programmi e l’input automatico.

    StreamUno stream è un canale di comunicazione monodirezionale (o di input o di output), di uso generale, che trasferisce byte o caratteri. È un oggetto che fa da buffer tra sorgente e destinazione. System.in è un input stream (tastiera), System.out un output stream (video). In C++: std::cin, std::cout.

    Il package java.io permette di aprire, usare (read/write) e chiudere uno stream. La difficoltà non è usare una classe, ma capire quale classe usare.

    File di testo e file binari

    Testo

    I bit rappresentano caratteri stampabili (ASCII: un byte per carattere). Leggibili da una persona. Es. i sorgenti .java. Il numero 127 occupa 3 byte: “1”, “2”, “7” (49, 50, 55).

    Binari

    I bit codificano altre informazioni (istruzioni, numeri). Leggibili solo dal computer, più efficienti. Es. i .class. Il numero 127 occupa 1 byte (byte), 2 (short) o 4 (int).

    Buffering

    Non bufferizzato

    Ogni byte letto o scritto sul disco appena possibile: un’operazione su disco per byte, overhead alto.

    Bufferizzato

    Lettura/scrittura a blocchi (es. 16 byte): un po’ di attesa, ma un’operazione su disco per buffer, overhead basso.

    Le quattro classi base astratte

    InputOutput
    Stream di byte (come i file binari del C)InputStreamOutputStream
    Stream di caratteri (come i file di testo, da Java 1.1)ReaderWriter

    Regola dei nomi: le classi che trattano byte contengono InputStream/OutputStream; quelle che trattano caratteri contengono Reader/Writer. Le classi base sono astratte: read() e write() li definiscono le sottoclassi per il dispositivo specifico.

    • OutputStream: il costruttore apre lo stream; write() scrive uno o più byte; flush() svuota il buffer; close() chiude.
    • InputStream: read() legge uno o più byte.
    • System.out è un PrintStream (print, println, write).

    Byte su file: FileOutputStream e FileInputStream

    Al costruttore si passa il nome del file (o un oggetto File). Un secondo parametro true apre in modalità append. write(int) scrive un byte (0–255); read() restituisce il byte come int tra 0 e 255, -1 a fine stream, e se non ci sono byte ma lo stream non è finito aspetta.

    Le operazioni di I/O possono fallire e lanciano IOException, che non si può ignorare: o si gestisce con try/catch, o si rimanda con throws.

    FileOutputStream os = null;
try {
    os = new FileOutputStream(args[0]);        // (args[0], true) per l'append
    for (int x = 0; x < 10; x += 3) os.write(x);   // scrive 0, 3, 6, 9: file di 4 byte
    os.close();
} catch (IOException e) {
    System.out.println("Errore di output");
}

FileInputStream is = new FileInputStream(args[0]);
int x = is.read(), n = 0;
while (x >= 0) {                  // read() restituisce -1 a fine stream
    System.out.print(" " + x); n++;
    x = is.read();
}
System.out.println("\nTotale byte: " + n);

    Leggere un byte per volta è scomodo. Gli stream di incapsulamento (filtri) avvolgono un altro stream per aggiungere funzionalità: il loro costruttore riceve un InputStream o un OutputStream. Si configura il canale con tutte e sole le funzionalità che servono, senza reimplementarle: massima flessibilità, minimo sforzo. Base: FilterInputStream / FilterOutputStream (“I/O filtrato”).

    StreamTokenizer

    Spezza un flusso di input in token (segmenti lessicali). Non deriva da InputStream (per le stringhe c’è StringTokenizer). Costanti: TT_EOF (fine flusso), TT_EOL (fine riga), TT_NUMBER (il token è un numero, in nval), TT_WORD (una parola, in sval). Il tipo del token corrente è in ttype; ordinaryChar('.') dice di trattare il punto come carattere normale.

    StreamTokenizer st = new StreamTokenizer(new BufferedReader(new InputStreamReader(System.in)));
while (st.nextToken() != StreamTokenizer.TT_EOF) {
    switch (st.ttype) {
        case StreamTokenizer.TT_NUMBER: System.out.println(st.nval); break;
        case StreamTokenizer.TT_WORD:   System.out.println(st.sval); break;
        default: System.out.println((char) st.ttype);
    }
}

    java.util.Scanner analizza testo (da String o da stream) in tipi primitivi e stringhe, usando espressioni regolari e lo spazio come delimitatore. È più flessibile e intuitivo di StreamTokenizer e split(), ma più lento (nelle slide: Scanner 10642 ms, split 715 ms, StringTokenizer 544 ms).

    Trabocchetto: nextInt seguito da nextLine

    Sincronizzato (adatto a più thread), buffer più grande, un po’ più veloce: legge solo caratteri.

    Scanner

    Non sincronizzato; fa il parsing dei dati (più lento).

    Da AWT a Swing, JFrame, chiusura della finestra, look and feel, pannelli e componenti.

    AWT

    Con Java 1.0 Sun fornisce l’Abstract Window Toolkit (AWT): la creazione e il comportamento degli elementi grafici sono delegati al toolkit nativo della piattaforma. Il programmatore indica posizione e comportamento, Java crea i peer nativi.

    Limiti: comportamenti diversi sulle varie piattaforme, esperienza poco coerente, libreria ridotta al minimo comune denominatore dei componenti, aspetto meno curato delle app native, bug diversi su piattaforme diverse.

    Swing

    Nel 1996 Netscape crea le Internet Foundation Classes (IFC): gli elementi (pulsanti, menu…) vengono dipinti in finestre vuote; dal sistema serve solo costruire le finestre e disegnarci. Sun, con Netscape, ne ricava Swing: i “widget” hanno lo stesso aspetto e comportamento su ogni piattaforma.

    • Swing non sostituisce del tutto AWT: offre componenti alternativi più ricchi (JButton rispetto a Button), ma l’architettura, in particolare la gestione degli eventi, resta quella di AWT.
    • I componenti Swing sono un po’ più lenti da visualizzare di quelli con peer (oggi trascurabile).
    • I nomi aggiungono una J davanti: JTextArea è la controparte di TextArea.
    • Vantaggi: più componenti, meno dipendenza dalla piattaforma, meno bug specifici, risultato coerente. Svantaggio: l’aspetto non è quello nativo; per questo Sun ha creato il look and feel indipendente Metal.

    Creare una finestra

    Si importa import javax.swing.*;. Si può mescolare AWT e Swing, ma è consigliato usare solo Swing. Una finestra top-level è un frame: in AWT Frame, in Swing JFrame (che estende Frame ed è uno dei pochi componenti Swing non disegnati su un canvas). I frame sono contenitori: insieme ai layout manager decidono come disporre i componenti.

    public class Semplice {
    public Semplice(String titolo) {
        JFrame frame = new JFrame(titolo);
        frame.setSize(500, 300);                                 // in pixel
        frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);    // evento di chiusura
        frame.setVisible(true);                                  // non è visibile per default
    }
    public static void main(String[] args) { new Semplice("Titolo"); }
}

    A ogni finestra è associato un thread: quando finisce il main il programma non termina.

    setDefaultCloseOperationAlla chiusura del frame
    EXIT_ON_CLOSETermina il programma.
    DISPOSE_ON_CLOSEChiude e libera solo il frame; il processo continua.
    DO_NOTHING_ON_CLOSEIgnora l’evento: il frame resta aperto.
    HIDE_ON_CLOSENasconde il frame (resta in memoria) e continua (es. Messenger).

    Altri metodi: setVisible(true/false) (o i vecchi show()/hide()), setBounds(x, y, larghezza, altezza).

    Look and feel: si cambia con UIManager.setLookAndFeel("javax.swing.plaf.metal.MetalLookAndFeel"); la classe deve essere disponibile sul sistema.

    Pannelli

    In Swing non si aggiungono componenti direttamente al frame: vanno in un pannello. Il frame ha diversi pannelli; quello che interessa è il content pane. I pannelli (JPanel) hanno una superficie su cui disegnare e sono a loro volta contenitori, anche di altri sottopannelli.

    public class FramePulsanti {
    JButton pulsanteUno = new JButton("Pulsante uno");
    JButton pulsanteDue = new JButton("Pulsante due");
    public FramePulsanti() {
        JFrame frame = new JFrame("FrameDemo");
        frame.setSize(300, 80);
        JPanel pannello = new JPanel();
        pannello.add(pulsanteUno);
        pannello.add(pulsanteDue);
        pulsanteDue.setEnabled(false);
        frame.setContentPane(pannello);
        frame.setVisible(true);
    }
}

    Componenti: pulsanti, combo box, liste, menu, campi di testo, etichette, tooltip, barre di avanzamento, selettori di colore e di file, tabelle, alberi. Operazioni: setEnabled, setVisible, setSize, isEnabled, isVisible, getSize.

    Gestione degli eventi

    Sorgenti e ricevitori, tipi di eventi, interfacce Listener, ActionListener, MouseListener, Adapter.

    Ogni azione dell’utente su un elemento grafico (click, tasto, finestra ridimensionata, voce di menu) genera un evento.

    Sorgente (source)

    Il componente grafico che genera l’evento (es. un JButton).

    Ricevitore (listener)

    L’oggetto che reagisce all’evento con i suoi metodi.

    Si implementa un ricevitore per ogni evento da gestire e lo si collega alla sorgente; quando l’evento si verifica, vengono attivati tutti i ricevitori di quel tipo collegati alla sorgente.

    Il package java.awt.event contiene le classi degli eventi, le interfacce Listener e alcune classi Adapter.

    EventoGenerato daListener
    ActionEventAzione di un componente, es. pressione di un pulsante (anche con la barra spaziatrice)ActionListener
    MouseEventClick, spostamento del mouseMouseListener
    KeyEventTasto premuto su un componente (es. JTextField)KeyListener
    FocusEventGuadagnare/perdere il focusFocusListener
    ItemEventSelezione/deselezione di un elementoItemListener
    AdjustmentEventValore numerico modificabile (es. JScrollBar)AdjustmentListener
    WindowEventCambio di stato di una finestraWindowListener

    ActionListener e JButton

    public class ClickListener implements ActionListener {
    public void actionPerformed(ActionEvent event) {   // eseguito al click
        System.out.println("I was clicked.");
    }
}
JButton b1 = new JButton("Button 1");
b1.addActionListener(new ClickListener());   // collega il ricevitore alla sorgente

    Il parametro event contiene i dettagli dell’evento (es. il momento; e.getSource() dà la sorgente). Se il listener deve usare variabili della finestra, conviene una classe interna. In alternativa la finestra stessa implementa ActionListener:

    public class ActionButton2 extends JFrame implements ActionListener {
    JButton b1 = new JButton("Button 1");
    JButton b2 = new JButton("Button 2");
    public ActionButton2() {
        super("ActionButton2");
        JPanel p = new JPanel();
        p.add(b1); p.add(b2);
        setContentPane(p);
        b1.addActionListener(this);
        b2.addActionListener(this);
    }
    public void actionPerformed(ActionEvent e) {
        String name = ((JButton) e.getSource()).getText();   // quale pulsante?
        System.out.println("You have clicked " + name);
    }
}

    Eventi del mouse e Adapter

    Si usa un MouseListener, aggiunto con addMouseListener. L’interfaccia ha cinque metodi (mouseClicked, mousePressed, mouseReleased, mouseEntered, mouseExited): vanno implementati tutti, anche vuoti.

    Per non doverli scrivere tutti, per ogni listener con più metodi esiste un Adapter, una classe che implementa l’interfaccia con tutti i metodi vuoti: si estende e si ridefinisce solo quello che serve.

    class MyMouseListener extends MouseAdapter {
    public void mouseClicked(MouseEvent e) { /* risponde al click */ }
}
    In tre passiPer gestire un evento: 1) definire una classe che implementa un’interfaccia Listener (o estende un Adapter); 2) ridefinire i metodi dell’interfaccia; 3) aggiungere il listener al componente con addXxxListener.

    Implementa un listener con tutti i metodi vuoti: si ridefinisce solo quello che serve.

    Classi anonime interne

    Permettono di implementare una classe usata una sola volta, senza darle un nome né un file a parte. Uso tipico: i gestori di eventi nelle interfacce grafiche.

    testButton.addActionListener(new ActionListener() {
    @Override

        System.out.println("Test Button clicked");

});

    Evitano di scrivere n classi che implementano ActionListener e definiscono la classe dove serve. Ma per un’interfaccia con un solo metodo la sintassi resta pesante.

    Interfacce funzionali

    DefinizioneUn’interfaccia funzionale (Java 8) ha un solo metodo astratto (può avere anche metodi default e static). Esempi: ActionListener, Runnable, Comparator, Consumer, Predicate, FileFilter. Sono le interfacce usate dalle espressioni lambda.

    Le espressioni lambda

    Introdotte in Java SE 8, portano uno stile di programmazione funzionale (derivano dal lambda calcolo). Una lambda è una funzione anonima: un metodo senza dichiarazione, scritto dove serve, che si può passare come argomento o restituire. Rende il codice più chiaro e meno verboso, soprattutto per funzioni brevi usate una volta.

    (lista degli argomenti) -> espressione
(lista degli argomenti) -> { istruzioni; }

(int x, int y) -> x + y                 // somma di due interi
s -> s.length()                         // lunghezza di una stringa
() -> 50                                // nessun argomento, restituisce 50
(String s) -> { System.out.println("Benvenuto"); System.out.println(s); }

testButton.addActionListener(e -> System.out.println("Click Detected by Lambda Listener"));
    • Il tipo dei parametri si può omettere; con un solo parametro anche le parentesi.
    • Con una sola espressione il valore viene restituito da solo; con un blocco servono le graffe e il return.

    Cattura delle variabili

    Una lambda accede a campi, metodi e variabili locali del contesto che la contiene. Ma a differenza delle classi interne non crea un nuovo livello di scope: è valutata lessicalmente, come il codice intorno.

    • Non si può chiamare un parametro della lambda come una variabile locale già esistente: errore “variable x is already defined”.
    • this dentro una lambda è l’oggetto che la contiene, non la lambda.
    • Le variabili locali e i parametri usati dalla lambda devono essere final o effettivamente final (assegnati una sola volta). Altrimenti: “local variables referenced from a lambda expression must be final or effectively final”.

    Perché: le variabili locali stanno nello stack e possono sparire quando il metodo finisce, mentre la lambda (es. in un altro thread) può essere eseguita dopo. La lambda lavora quindi su una copia, che deve restare uguale all’originale.

    Ombreggiamento nelle classi interne (esempio ShadowTest con x = 0 nella classe esterna, x = 1 nella interna e il parametro x = 23): x → 23, this.x → 1, ShadowTest.this.x → 0.

    Riferimenti a metodi

    Quando una lambda si limita a chiamare un metodo esistente, si può scrivere direttamente il riferimento al metodo con ::.

    Arrays.sort(rosterAsArray, (a, b) -> Person.compareByAge(a, b));
Arrays.sort(rosterAsArray, Person::compareByAge);    // equivalente
    TipoSintassi
    Metodo staticoContainingClass::staticMethodName
    Metodo d’istanza di un oggetto particolarecontainingObject::instanceMethodName (es. myComparisonProvider::compareByName)
    Metodo d’istanza di un oggetto arbitrario di un tipoContainingType::methodName (es. String::compareToIgnoreCase)
    CostruttoreClassName::new

    Quando usare cosa

    • Classe interna non statica per accedere a campi e metodi non pubblici dell’oggetto esterno; statica se non serve.
    • Classe locale per creare più istanze, usare un costruttore, introdurre un nuovo tipo.
    • Classe anonima se servono campi o metodi aggiuntivi.
    • Lambda per passare una singola unità di comportamento, o una singola istanza di un’interfaccia funzionale.

    No: con return servono le graffe.

    Stream

    Creare uno stream, pipeline, operazioni intermedie e terminali, lazy, Optional, reduce, collect, groupingBy, partitioning, ricerca.
    DefinizioneUno stream (Java 8) è una sequenza di oggetti presi da una sorgente a cui si applica una sequenza di operazioni, con un approccio dichiarativo (simile a SQL). Consente l’accesso sequenziale agli elementi, supporta operazioni di aggregazione e molte operazioni restituiscono stream, quindi si concatenano.
    • Non c’entrano niente con InputStream e OutputStream.
    • Non sono strutture dati: avvolgono la sorgente e trasportano i valori lungo una pipeline.
    • Sono pensati per le lambda, usano la valutazione lazy e sono parallelizzabili.

    Creare uno stream

    Stream.of(val1, val2, ...);          // da valori
Stream.of(someArray);  Arrays.stream(someArray);   // da array
someList.stream();                   // da una Collection
Stream<String> empty = Stream.empty();

IntStream intStream = IntStream.range(1, 10);      // per i primitivi: IntStream, LongStream, DoubleStream
IntStream chars = "rosso".chars();                  // niente CharStream: i char sono IntStream
DoubleStream casuali = new Random().doubles();      // infinito
Stream<String> righe = Files.lines(Paths.get("data.txt"));   // da file (NIO)
Stream.iterate(0, n -> n + 2).limit(10);            // infinito, da un seme
Stream.generate(Math::random).limit(5);             // infinito, da un Supplier
Stream.ofNullable(System.getProperty("home"));      // Java 9: vuoto se il valore è null

    La pipeline

    Sorgente→0 o più operazioni intermedie→1 operazione terminale

    Operazioni intermedie

    Restituiscono uno Stream, quindi si concatenano. Sono lazy: non vengono eseguite finché non c’è un’operazione terminale. filter, map, flatMap, distinct, sorted, peek, limit, skip, parallel.

    Operazioni terminali

    Restituiscono un tipo definito (primitivo, collezione, void) e consumano lo stream: dopo non si può più usare. forEach, toArray, reduce, collect, min, max, count, anyMatch, allMatch, noneMatch, findFirst, findAny.

    Short-circuit: anyMatch, allMatch, noneMatch, findFirst, findAny, limit fanno elaborare gli elementi precedenti solo finché non hanno la risposta.

    mapToIntToIntFunctionProduce un IntStream (con sum, average…).

    Esterna (for-each, Iterator)

    L’applicazione decide quale collezione e come iterarla (next()). Solo accesso sequenziale.

    Interna (operazioni aggregate)

    L’applicazione decide quale collezione, il JDK decide come. Può sfruttare l’elaborazione parallela.

    Collezioni immutabili

    Prima di Java 9 serviva Collections.unmodifiableList(lista). Da Java 9: List.of(…). Aggiungere, togliere o modificare lancia UnsupportedOperationException; i null lanciano NullPointerException.

    Optional

    Un contenitore che può avere un valore o essere vuoto, per non riempire il codice di controlli sul null.

Map<Person.Sex, List<String>> namesByGender =
    roster.stream().collect(Collectors.groupingBy(Person::getGender,
                            Collectors.mapping(Person::getName, Collectors.toList())));

Map<Boolean, List<Dish>> partitioned =
    menu.stream().collect(Collectors.partitioningBy(Dish::isVegetarian));
// {false=[pork, beef, salmon], true=[french fries, rice, fruit]}
    • groupingBy crea una mappa le cui chiavi sono i valori della funzione di classificazione. Con un secondo argomento (downstream collector) si fa una riduzione a più livelli.
    • partitioningBy è un caso speciale con chiave booleana: a differenza di filter dà entrambe le liste.

    Slicing e ricerca

    • takeWhile(pred) (Java 9) prende gli elementi finché il predicato è vero e poi si ferma, invece di scorrere tutto come filter; dropWhile(pred) scarta quelli iniziali finché è vero.
    • anyMatch (almeno uno), allMatch (tutti), noneMatch (nessuno) restituiscono un boolean.
    • findFirst (il primo), findAny (uno qualsiasi) restituiscono un Optional.

    Stream e Collection

    Collection

    Struttura dati in memoria con tutti i valori; costruita in modo eager; si può attraversare più volte.

    Stream

    Elementi calcolati su richiesta (lazy), non si aggiungono né tolgono; si attraversa una sola volta, poi è consumato.

    No, sono lazy: partono solo con l’operazione terminale.

    No: è consumato.

    Trasforma ogni elemento in uno stream e unisce tutto in un unico stream.

    L’identity: valore di partenza e risultato se lo stream è vuoto.

    partitioningBy.

    Gestione delle eccezioni

    Checked e unchecked, gerarchia, try, catch, finally, throw e throws, eccezioni personalizzate, printStackTrace, System.err.

    In C e in altri linguaggi gli errori si segnalano per convenzione (un valore di ritorno, un flag) e si spera che chi chiama controlli. Ma chi usa una libreria tende a non farlo.

    Il momento ideale per trovare un errore è la compilazione; gli altri vanno gestiti a run-time, altrimenti producono risultati sbagliati o comportamenti imprevisti. Cause frequenti: memoria (null pointer, memory leak), file system (disco pieno, file mancante), rete, calcolo (divisione per zero), array (indice -1), conversione (‘q’ in numero).

    Esempio: chi implementa la divisione non sa cosa fare se il divisore è zero, perché non conosce il contesto: lancia un’eccezione invece di continuare.

    La gerarchia

    Object→Throwable→Error·Exception→RuntimeException
    • Throwable: in cima alla gerarchia delle eccezioni, sottoclasse diretta di Object.
    • Error: problemi gravi dell’ambiente (es. StackOverflowError), non recuperabili: non si gestiscono nel codice.
    • Exception: condizioni che l’applicazione può dover gestire.

    Checked (controllate)

    Tutte le sottoclassi di Exception tranne RuntimeException. Condizioni recuperabili (es. IOException). Devono essere gestite: o in un try-catch, o delegate al chiamante con throws. Il compilatore lo controlla.

    Unchecked (non controllate)

    Sottoclassi di Error e RuntimeException (es. NullPointerException, ArrayIndexOutOfBoundsException). Di solito errori di programmazione; possono capitare ovunque, quindi gestirle sempre appesantirebbe il codice senza renderlo più robusto. Gestirle non è obbligatorio.

    try, catch, finally

    Il blocco try contiene il codice che può lanciare eccezioni. Se un’istruzione lancia un’eccezione, le istruzioni successive del try non vengono eseguite e si salta all’exception handler, il blocco catch che segue.

    try {
    // codice che può generare eccezioni
} catch (Type1 id1) {
    // gestisce Type1
} catch (Type2 id2) {
    // gestisce Type2
} finally {
    // eseguito SEMPRE, che ci sia stata un'eccezione o no
}
    • Viene eseguito un solo catch: il primo compatibile con l’eccezione.
    • Ordine: dal particolare al generale, con catch (Exception e) per ultimo.
    • finally (che il C++ non ha) serve a rilasciare le risorse: file, socket… Il garbage collector libera solo la memoria.
    Trabocchetto: l’ordine dei catch
    try { do_smtg(); }               // lancia MyException extends Exception
catch (Exception ex) { ... }
catch (MyException my_ex) { ... }
    Le slide dicono che il primo catch viene sempre eseguito e il secondo mai. In Java, di più: il codice non compila (“exception MyException has already been caught”). Il catch più specifico va prima.

    Con il try-with-resources la risorsa viene chiusa da sola alla fine:

    try (BufferedWriter bw = new BufferedWriter(new FileWriter("myFile.txt"))) {
    bw.write("Test");
} catch (IOException ioe) {
    ioe.printStackTrace();
}

    Cosa succede quando si lancia un’eccezione

    1. Si crea un oggetto eccezione, come qualunque oggetto (new Exception()).
    2. Il percorso di esecuzione si ferma e il riferimento all’eccezione viene espulso dal contesto corrente: si dice che il codice solleva (throw) l’eccezione.
    3. Il meccanismo cerca un exception handler da cui riprendere, risalendo lo stack delle chiamate (“srotolamento”) fino a un catch adatto.
    4. Se non lo trova, il programma termina.

    throw e throws

    throw

    Lancia un’eccezione: throw new ErroreStringaVuota();

    throws

    Nella firma: dichiara che il metodo può lanciare quelle eccezioni (controllate) e ne delega la gestione al chiamante.

    public void stampa(String a) throws ErroreStringaVuota {
    if (a == null) throw new ErroreStringaVuota();
    else System.out.println(a);
}

    Un catch che non riesce a gestire tutto l’errore può fare quel che può e rilanciare l’eccezione al livello esterno: in Java con throw e;.

    Alcune slide mescolano sintassi C++: throw; senza argomenti, catch (…), std::unexpected() e std::terminate() sono del C++. In Java si rilancia con throw e; e si cattura tutto con catch (Exception e) (o Throwable).

    Creare una propria eccezione

    Si estende Exception (eccezione controllata) definendo due costruttori: quello di default e quello con una stringa.

    class SimpleException extends Exception {
    public SimpleException() {}
    public SimpleException(String msg) { super(msg); }
}
public class SimpleExceptionDemo {
    public void f(int i) throws SimpleException {
        if (i > 0) throw new SimpleException("Throw SimpleException from f()");
    }
    public static void main(String[] args) {
        try { new SimpleExceptionDemo().f(5); }
        catch (SimpleException e) { System.err.println("Caught it!"); }
    }
}
    Le slide dicono che le eccezioni lanciate “da noi” sono controllate e quelle di Java no. Più precisamente: è controllata ogni eccezione che estende Exception ma non RuntimeException, chiunque la lanci (IOException è di Java ed è controllata).

    Eccezioni predefinite

    La JVM ne lancia alcune da sola: NullPointerException (riferimento null), ArrayIndexOutOfBoundsException (indice oltre la lunghezza). Si possono catturare come le altre. Tutte le eccezioni standard hanno due costruttori: quello di default e quello con un messaggio (new NullPointerException("t = null")).

    Metodi di Throwable

    • getMessage(): la descrizione dell’eccezione.
    • printStackTrace() (anche su un PrintStream o PrintWriter): stampa lo stack delle chiamate dal punto più esterno fino a quello dell’eccezione, con i numeri di riga. Molto utile per il debug.

    System.err

    È lo standard di uscita per gli errori, simile a System.out. Avere due stream permette di redirigere l’output lasciando invariati gli errori (o viceversa): System.setErr(new PrintStream(new FileOutputStream("file.txt")));, e System.setOut() per l’output normale.

    Approfondimento
    Obj

    La classe Object

    Dispensa senza numero: toString, equals e le sue proprietà, hashCode, getClass, finalize, instanceof, clone e Cloneable.

    Object è la superclasse, diretta o indiretta, di ogni classe. Definisce il comportamento base di ogni oggetto: confrontarsi con un altro oggetto, convertirsi in stringa, restituire la propria classe, attendere e notificare su una variabile condition.

    Si possono ridefinire

    clone, equals / hashCode, finalize, toString.

    Non si possono ridefinire (final)

    getClass, notify, notifyAll, wait.

    toString

    Restituisce una rappresentazione testuale; viene chiamato da solo quando serve una stringa ("…" + object, System.out.println(object)). La versione di Object restituisce getClass().getName() + '@' + Integer.toHexString(hashCode()), es. BankAccount@7ced01. Si consiglia di ridefinirlo sempre: è comodo per il debug.

    public String toString() { return "BankAccount[balance=" + balance + "]"; }

    equals

    La versione di Object usa ==: vero solo se è lo stesso oggetto. Ma l’uguaglianza dipende dall’applicazione: due conti sono uguali se hanno lo stesso saldo.

    public boolean equals(Object obj) {
    if (!(obj instanceof BankAccount)) return false;
    return ((BankAccount) obj).balance == balance;
}

    equals deve essere una relazione di equivalenza sui riferimenti non null:

    ProprietàRegola
    Riflessivax.equals(x) è true.
    Simmetricax.equals(y) è true se e solo se y.equals(x) è true.
    TransitivaSe x.equals(y) e y.equals(z), allora x.equals(z).
    ConsistenteChiamate ripetute danno sempre lo stesso risultato, se gli oggetti non cambiano.
    Con nullx.equals(null) è false.

    hashCode

    Se ridefinisci equals, devi ridefinire hashCode. hashCode restituisce un codice per le tabelle hash; quello di Object deriva dall’indirizzo interno dell’oggetto.

    • Chiamato più volte nella stessa esecuzione, dà sempre lo stesso valore se non cambiano le informazioni usate da equals (può cambiare tra esecuzioni diverse).
    • Se due oggetti sono uguali per equals, devono avere lo stesso hashCode.
    • Non è obbligatorio, ma consigliato, che oggetti diversi abbiano hashCode diversi.
    public int hashCode() { return (int) balance; }

    getClass e instanceof

    public final Class getClass() restituisce un oggetto Class che descrive la classe a run-time: nome della classe, della superclasse, interfacce implementate. obj.getClass().getName(); obj.getClass().newInstance() crea un oggetto della stessa classe.

    espressione instanceof TipoRiferimento è vero se il valore non è null e si può fare il cast a quel tipo senza ClassCastException; altrimenti falso. Se l’espressione non è di tipo riferimento, errore di compilazione.

    finalize

    Quando il GC raccoglie l’oggetto chiama finalize per il cleanup delle risorse diverse dalla memoria (connessioni, file). Si può ridefinire, ma non è consigliato per gestire risorse scarse.

    clone e Cloneable

    protected Object clone() throws CloneNotSupportedException. La versione di Object:

    • controlla che l’oggetto implementi Cloneable, altrimenti lancia CloneNotSupportedException;
    • crea un nuovo oggetto dello stesso tipo e copia gli attributi uno a uno (shallow copy).
    • Object non implementa Cloneable: una classe che non lo implementa non è clonabile.
    • Cloneable non contiene il metodo clone: dice solo che la copia campo per campo è lecita. Per convenzione la classe ridefinisce clone come public.
    • Chi usa Object.clone deve catturare l’eccezione.
    public class Stack implements Cloneable {
    private Vector items;
    public Object clone() {
        try {
            Stack s = (Stack) super.clone();        // copia superficiale
            s.items = (Vector) items.clone();       // copia profonda del campo mutabile
            return s;
        } catch (CloneNotSupportedException e) {
            throw new InternalError();              // non succede: Stack è Cloneable
        }
    }
}

    Regole empiriche: una classe deve clonare i riferimenti a oggetti mutabili che distribuisce (es. getAccount() restituisce conto.clone()) e quelli che riceve (il costruttore salva unConto.clone()).

    Regola di progettazione
    x.clone() != xDEVE essere vera
    x.clone().getClass() == x.getClass()DEVE essere vera
    x.clone().equals(x)PUÒ essere vera

    Per convenzione clone non usa new e non chiama costruttori, ma super.clone(): se tutta la gerarchia lo rispetta, il clone ha la classe giusta.

    Domande lampo

    Overloading e overriding: differenza?

    Overloading: stesso nome, parametri diversi, risolto a compile-time. Overriding: stessa firma in una sottoclasse, risolto a run-time.

    Classe astratta o interfaccia?

    La classe astratta può avere attributi e codice e se ne estende una sola; l’interfaccia ha costanti e metodi astratti (più default/static) e se ne implementano molte.

    Upcasting e downcasting?

    Upcasting implicito e sempre sicuro; downcasting esplicito, controllato a run-time, può lanciare ClassCastException.

    Che cosa garantisce il polimorfismo?

    Che lo stesso messaggio esegua il metodo della classe effettiva dell’oggetto: il codice si estende senza modificarlo.

    Copia superficiale o profonda?

    Superficiale: copia i riferimenti agli oggetti interni. Profonda: duplica anche quelli.

    Checked o unchecked?

    Checked: Exception tranne RuntimeException, vanno gestite o dichiarate. Unchecked: RuntimeException ed Error.

    Perché lo stream si dice lazy?

    Perché le operazioni intermedie partono solo quando c’è un’operazione terminale.

    A cosa serve final su metodo e classe?

    Metodo: non si può ridefinire. Classe: non si può estendere.
